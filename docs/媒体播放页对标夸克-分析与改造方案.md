# 媒体播放页对标夸克：分析与改造方案

> 范围：视频播放页、音频播放页、图片浏览页的**布局结构**。
> 依据：夸克网盘 6 张实机截图 + 本仓库现有代码（含行号）。
> 结论性质：可行性分析 + 分阶段施工单，不含本次代码改动。

---

## 一、结论摘要

1. 夸克"好看"的本质不是配色，而是**三类媒体页共用一套四层骨架**：内容全出血 → 悬浮顶栏（居中两行标题 + `···`）→ 浮层胶囊 → 底部「图标 + 文字」等分动作栏。
2. 更关键的是**显隐**：播放页默认**零控件**，点一下才出控制层，3～5 秒自动收起（横屏还有锁屏键）。我们目前是**三层 chrome 常驻**，画面被压成中间一小条。
3. 我们的"丑"有三个可分离的成因：① chrome 常驻；② 动作行 7 项权重不对称（播放键恒定偏左 50dp）；③ 缺「图标 + 文字」的动作栏语言。
4. 其中 **①② 是纯布局改动，零业务风险**，两三天内可落地；③ 里的图片页动作栏也可直接做，音频大封面属中等改造。
5. **不建议照搬**的：竖屏"详情页"结构（需重排页面栈）、AI 总结/文稿 Tab（无对应能力）、转文字、修图。

### 可行性总览

| 级别 | 含义 | 项数 |
|---|---|---|
| A 直接做 | 纯布局，无接口/数据依赖 | 9 |
| B 小改造 | 需新增菜单/抽屉/组件，或补少量状态 | 5 |
| C 需验证 | 依赖缩略图取址、文件落盘等外部条件 | 3 |
| D 不建议 | 与现有架构或能力冲突 | 3 |

## 二、夸克的设计骨架

### 2.1 四层骨架

| 层 | 做法 | 关键尺寸信号 |
|---|---|---|
| L0 内容 | 图片/视频**全出血**，顶到状态栏下 | 无内边距、无卡片 |
| L1 顶栏 | 透明或渐变，左返回 + **居中两行标题** + 右侧 ≤2 个动作，其余收 `···` | 高 44–52dp；主标题 15–16sp；副标题 11–12sp 灰 |
| L2 浮层胶囊 | 单条信息浮在内容上 | 高 24–26dp，圆角 12–13，`#26FFFFFF` 底，文字 11–12sp |
| L3 动作栏 | **图标 24 + 标签 11sp 等分网格** | 高 56dp，5–6 格等分 |
| L4 播放条 | `时间 — 2dp 轨道 + 圆点 — 时间` 同排 | 轨道 2dp，拇指 8dp，时间 11–12sp |

### 2.2 六张截图逐图拆解

| 图 | 页面 | 从上到下的层级 | 值得抄的点 |
|---|---|---|---|
| 1 | 视频·横屏 | 透明顶栏（返回/标题/投屏/耳机/小窗/`···`）→ 画面（左中锁屏、右中 AI 总结·旋转）→ 底部 `暂停 + 01:09 + 细轨道 + 44:06` → 次行 `网速提示 / 字幕·选集·倍速·音效·SVIP` | 播放键与进度同排；动作下沉成文字行；锁屏 |
| 2 | 视频·竖屏详情 | 16:9 播放器（无 chrome）→ `视频/​AI总结/​文稿` Tab → 标题 17sp + 时间灰字 + `文件目录 >` → 分隔线 → `选集`段头 + 系列名 + `全部 ▾` → 缩略图列表 | 播放器只是页首一块；列表有缩略图与徽标 |
| 3 | 同图 2（带续播提示） | 播放器底部浮层胶囊「上次观看至 00:21 已为您自动续播」 | 提示不占版面 |
| 4 | 文件列表（音频目录） | 顶栏（返回/标题/搜索/关闭）→ 面包屑胶囊 → `按文件名 ↑` + 视图切换 → 行（类型图标 / 两行文本 / 单选圈）→ 悬浮迷你播放器 | 面包屑做成胶囊；行内两行信息 |
| 5 | 音频播放 | `⌄` + `···` → **大封面（≈260dp 圆角）** → 标题 17–18sp 居中 → 5 格动作（倍速/定时/下载/收藏/转文字）→ `时间—轨道—时间` → 传输控制 | 大封面是唯一主体；动作 5 格 |
| 6 | 图片浏览 | 透明顶栏（返回 / 日期+时间 两行居中 / `···`）→ 图片全出血 → `原图 600.2KB` 胶囊 → 6 格动作（分享/修图/横屏/收藏/下载/删除） | 两行标题；动作栏；信息胶囊 |

### 2.3 显隐机制（本次最该抄的一条）

| 状态 | 表现 |
|---|---|
| 默认 | 只有画面，顶栏、进度、动作行全部不显示 |
| 单击 | 控制层淡入（顶栏 + 进度 + 动作行），**同时**出现 |
| 3～5 秒无操作 | 自动淡出 |
| 横屏锁屏后 | 点击也不再出现，防误触 |

推论：**倍速这类低频动作，在夸克里本来就不常驻**。所以对标时优先修"常驻"，再谈"位置"。

## 三、我方现状盘点

### 3.1 视频播放页

结构：`VideoPlaybackPage` 是一个 **Dialog**（`Theme_Material_NoActionBar`），宿主为 `MainActivity`；内部 `PlayerView`（`view_video_player.xml`）+ 自绘顶栏 + 覆盖式课程面板。

| 元素 | 现状 | 代码位置 |
|---|---|---|
| 容器 | Dialog 全屏，`content` 上留 52dp 给顶栏 | VideoPlaybackPage.kt:497-499 |
| 顶栏 | 实色 `0xD9111118`，返回 + 标题 + 定时/收藏/纯音频/选集 **4 个纯图标** | :462-475 |
| 控制条 | ExoPlayerView 自定义 `exo_bottom_bar`：进度行（32dp）+ `videoActions`（48dp 七项） | view_video_controls.xml |
| 动作行 | `[上一节][-10][播放 44][+10][下一节][倍速 56][全屏 44]`，4 项 `weight=1` | :250-262 |
| 显隐 | `controllerShowTimeoutMs = 0`、`controllerHideOnTouch = false`；仅全屏 3s 收 | :93-94、:701 |
| 顶栏随隐 | `if (immersive) 跟随 else 恒显` | :691 |
| 课程面板 | 直接盖在视频区域上，`0xFF15151D` | :305、:498-499 |

### 3.2 音频播放页

| 元素 | 现状 | 代码位置 |
|---|---|---|
| 顶栏 | 52dp：返回 + 居中「音频播放」+ 定时/收藏/停止 | MainActivity.kt:4499、:4430-4450 |

### 3.3 图片浏览页

| 元素 | 现状 | 代码位置 |
|---|---|---|
| 顶栏 | 48dp 实色 `argb(190)`：返回 + 单行标题 + 「用其他应用打开」文字按钮 | ImageViewerActivity.kt:159、:171-195 |
| 内容 | 黑底全屏 `ZoomImageView` | :141-152 |
| 底栏 | 文字三栏「上一张 / 3/9 / 下一张」，仅 `count>1` 时出现 | :200-221 |
| 能力 | 仅有：上一张、下一张、用其他应用打开、原图回退 | :311-377 |

### 3.4 共性归因

```
视频：顶栏常驻 + 控制条常驻 + 课程面板覆盖 = 三层 chrome
音频：顶栏 + 小封面 + 控制卡片 + 常驻列表 = 四块等权重堆叠
图片：实色顶栏 + 文字三栏底栏 = chrome 最重、能力最弱
```

三者都是"控件围着一块内容"，而夸克是"内容本身就是页面"。

### 判定依据（为什么是 A）

- A 类全部只碰 `View` 的构造参数与 `LayoutParams`，不新增数据流、不改接口调用。
- 三个页面都是**程序化 UI**（Kotlin `new View`），除 `view_video_controls.xml` 与 `app_main.xml` 外无 XML 依赖，改动集中。
- 沉浸式所需能力已具备：`updateSystemBars()`（VideoPlaybackPage.kt:864-877）+ 手势层（:552-688）。

## 五、分阶段实施计划

### 阶段 0 · 控制层显隐（最高优先，收益最大）

| 项 | 内容 |
|---|---|
| 目标 | 默认态只剩画面；点一下出控制层；3s 自动收 |
| 文件 | `VideoPlaybackPage.kt` |
| 改动 | ① `controllerShowTimeoutMs` 统一为 `3000`（:93、:701）；② 用 `PlayerView.setControllerVisibilityListener` 同步顶栏/缓冲提示的显隐，替换 :691 的写死逻辑；③ 保留 `controllerHideOnTouch = false`，单击显隐仍由手势层（:593）单点触发，避免双击切两次 |
| 分档 | **横屏全屏**：顶栏随控制层完全隐藏；**竖屏/小窗**：控制层 3s 收，但顶栏保留（透明 + 44dp 返回 + 标题），否则用户没有返回入口 |
| 验收 | 竖屏首屏无控制条、无实色顶栏；点画面出现，3s 后消失；返回键随时可用；缓冲提示不被误藏 |

### 阶段 1 · 动作行对称 + 倍速归位

| 项 | 内容 |
|---|---|
| 目标 | 播放键回到中线；倍速/全屏不再参与传输控制排布 |
| 文件 | `VideoPlaybackPage.kt:250-262`、`view_video_controls.xml`、新增 `bg_video_speed.xml` |
| 改动 | ① 动作行只留 5 项：`上一节 / -10s / 播放(48dp 固定) / +10s / 下一节`，左右各 2 个 `weight=1` → 播放键中心恒等于容器中心；② 进度行右端新增 settings 容器，放 `1.0x` 胶囊（高 24、文字 11sp、`#26FFFFFF`）与 32dp 全屏图标；③ `PopupMenu` 锚点改到胶囊上 |
| 验收 | 480dp / 720dp 两种宽度下，播放键中心与容器中心误差 0；`1.0x` 在时长右侧 8dp；弹窗锚点不越界 |

### 阶段 2 · 图片浏览页动作栏

| 项 | 内容 |
|---|---|
| 目标 | 顶栏两行标题 + 底部 4 格动作栏 |

| 验收 | 默认态顶栏与底栏叠在图上不遮关键内容；单张图片时动作项自动隐藏；翻页后序号即时更新 |

### 阶段 3 · 音频页沉浸化

| 项 | 内容 |

| 验收 | 首屏三要素：封面、标题、进度条；列表默认不占屏；收起即回到播放 |

## 七、风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 竖屏藏顶栏后无法返回 | Dialog 没有系统返回键，也没有底部导航 | 竖屏只藏控制条，顶栏保留但透明化；横屏才全隐 |
| 单击显隐重复触发 | `controllerHideOnTouch=true` 与手势层 `:593` 两处都切 | 保持 `false`，显隐只走手势层 |
| 亮画面白字不可读 | 顶栏透明后失去衬底 | 顶栏加深色 scrim；仅在亮帧区域判断的复杂度不值得做 |
| insets 与沉浸冲突 | Android 15 强制 edge-to-edge | 复用 `updateSystemBars()`，勿另写一套 |
| 无 Material 依赖 | 音频抽屉、圆角 BottomSheet 不可直接用 | 先自写 `Panel`（`TranslateAnimation` + `GestureDetector`），或后置 |
| 缩略图接口不确定 | 视频缩略图可能拿不到 | 先做 spike，再决定是否投入 |
| 倍速弹窗被 3s 自动收打断 | 控制条隐藏会带走锚点 | 弹菜单期间临时 `controllerShowTimeoutMs = 0`（现有 :233、:395 已有此写法，保留） |
