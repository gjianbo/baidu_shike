# 群组文件库 · 媒体取址技术方案（视频 / 音频 / 文档）

> 版本：v1.0　生成日期：2026-11-07　适用：网页版 IM 群组文件库（doc_lib，非分享链接）
> 结论来源：全部为**真实账号登录态下的实测**（不是文档推断），证据见第 11 节。
> 读者：客户端开发。目标——照着本文即可对视频、音频、文档分别拿到「可播地址 / 可下载地址」。

---

## 0. 一句话总览

| 文件类型 | 在线**播放**地址 | **原始文件**地址 | 关键接口 |
|---|---|---|---|
| **视频**（mp4 等） | ✅ HLS 转码流 `M3U8_AUTO_480` | ✅ `sharedownload` 的 dlink | `/mbox/msg/streaming`、`/api/sharedownload` |
| **音频**（mp3/m4a 等） | ✅ HLS 转码流 `M3U8_MP3_128` | ✅ `sharedownload` 的 dlink（原始 mp3） | 同上 |
| **文档**（pdf/doc/zip 等） | ❌ 不可转码（返回 31304） | ✅ **只能** `sharedownload` 的 dlink | 仅 `/api/sharedownload` |

**核心认知：**
1. 列表里点开的 `pfile/mboxvideo?...` 是 **HTML 播放器页，不是地址**，必须跳过它，自己发取址请求。
2. **音视频**有两套地址：`streaming`（转码 HLS，在线播）和 `sharedownload`（原始文件直链，下载/离线）。
3. **文档**没有 `streaming`（转码服务只认音视频），只有 `sharedownload` 的 dlink 一条路。
4. 所有接口**只认 Cookie 登录态 + 同源**（不能脱离浏览器/WebView 用裸 HTTP 重放）。

## 1. 名词与 ID 体系（务必先分清）

| 名称 | 出现位置 | 含义 | 位数示例 |
|---|---|---|---|
| `gid` = `to` | listshare 的 `gid`；mboxvideo 的 `to`；streaming 的 `to` | **库/会话稳定 ID**，同一个库整库不变 | 17 位，如 `23519283863221172` |
| `msg_id` | 列表 `msg_list[].msg_id`；mboxvideo 的 `msg_id`；streaming 的 `msg_id` | **消息 ID**（文件挂在哪条 IM 消息上），同一棵树内通常不变 | 19 位 |
| `fs_id` | 列表 `file_list[].fs_id` / recentv2 的 `fsid` | **文件 ID**，目录与文件各有一个 | 14~15 位 |
| `from_uk` = owner | 列表 `msg_list[].uk`；mboxvideo 的 `from_uk` | **上传者/分享者 uk** | 10 位 |
| viewer uk | `GET /api/gettemplatevariable?fields=["uk"]` 的 `result.uk` | **当前登录账号 uk**（=页面 URL 里 `#/im/session?fromId=` 的那个 `fromId`） | 9 位 |

> ⚠️ 易错点：`gid`（库）/`msg_id`（消息）/`fs_id`（文件）/`from_uk`（分享者）/`viewer uk`（自己）是**五个不同的东西**，不要混用。
> 实测已确认：`mboxvideo` 的 `to` 就是库 `gid`（同一值 `23519283863221172`）；`#/im/session?fromId=654702226` 的 `fromId` 就是 viewer uk（`gettemplatevariable` 返回 `uk=654702226`）。

## 2. 取址总决策表（按扩展名/类别分流）

```
判断 entry：
  ext = 文件名后缀小写
  若是 目录(isdir=1)            → 不取址，进入下钻
  若是 视频(mp4/mkv/mov/avi/flv/wmv/webm/ts/m4v …)
       播放地址 → streaming(stream_type=M3U8_AUTO_480/720/1080)
       原始文件 → sharedownload → dlink
  若是 音频(mp3/m4a/aac/flac/wav/wma/ogg/m4b/amr …)
       播放地址 → streaming(stream_type=M3U8_MP3_128)      // 转码，省事
       原始文件 → sharedownload → dlink                     // 原始 mp3，更省流量
  其他（pdf/doc/docx/ppt/xls/txt/zip/图片/未知）
       播放地址 → 无（streaming 必 400/31304，不要试）
       原始文件 → sharedownload → dlink                     // 唯一通路
```

## 3. 公共前提（所有取址都依赖）

1. **必须已登录**（`BDUSS` 等 Cookie 在 `pan.baidu.com` 域下）。
   - 未登录时任何接口返回 `errno:-6`（实测：listshare 脱 Cookie → `{"errno":-6,"show_msg":"请求超时，请稍后再试"}`）。
2. **必须同源发请求**（页面 `https://pan.baidu.com` 内，`credentials: 'include'` / `withCredentials=true`）。
   - 目的：让页面带 Cookie、并绕过跨域；同时接口需要的隐藏参数由页面环境自然满足。
   - **不要**用 OkHttp/curl 在 App 里裸重放（缺 Cookie 且接口会变）。
3. **取当前账号 uk**（`sharedownload` 的 body 需要）：
   ```
   GET /api/gettemplatevariable?clienttype=0&app_id=250528&web=1&fields=["uk"]
   → {"errno":0,"result":{"uk":654702226}}
   ```
   （在网盘页里也可直接读 `window.yunData` 的 uk，但实测该页面 `window.yunData` 为空，稳妥用上面接口。）
4. **列表数据来源**（拿到 fs_id/msg_id/from_uk/gid）——三选一：
   - 最近更新（跨库聚合）：`GET /imbox/file/recentv2?...&session_id=04_<gid>&id=1&channel=chunlei`
     → `data.recentlist[]`，每项有 `fsid / msg_id / fuk(=from_uk) / gid / server_filename / isdir / size / meta{...}`。
   - 库根列表：`GET /mbox/group/listshare?...&gid=<gid>&type=2&limit=50&desc=1`
     → `records.msg_list[]{ msg_id, uk, file_list[]{ fs_id, server_filename, path, isdir, size, ... } }`。
   - 目录下钻：`POST /mbox/msg/shareinfo?...&fs_id=<目录fsid>&msg_id=<msg_id>&from_uk=<uk>&gid=<gid>&type=2&page=1&num=100&limit=100&desc=1`（空 body；逐级只换 `fs_id`）。
5. **公共 Query 组**：`clienttype=0&app_id=250528&web=1`，加 `X-Requested-With: XMLHttpRequest`。

## 4. 视频取址

### 4.1 播放地址（HLS 转码流）

```
GET /mbox/msg/streaming
    ?from_uk=<from_uk>
    &to=<gid>
    &msg_id=<msg_id>
    &fs_id=<fs_id>
    &type=2
    &stream_type=M3U8_AUTO_480        // 可选 360/480/720/1080，非会员档位受限
    &clienttype=0&app_id=250528&web=1
Header: Cookie(登录态) ; X-Requested-With: XMLHttpRequest
→ 200  Content-Type: application/x-mpegURL
   #EXTM3U ... #EXTINF ... <分片URL> ... #EXT-X-ENDLIST
```

**实测（本条 mp4，396MB/31:34）**：200，226,737 字节，**media 列表**（`#EXT-X-STREAM-INF` 不存在），200 个分片，`#EXT-X-ENDLIST` 存在，`#EXT-X-KEY` 和 `#EXT-X-MAP` 均无（不加密），`#EXT-X-TARGETDURATION:10`；分片主机 `bdcm06.baidupcs.com`，路径 `netdisk-videotran-baoding/..._ts`。**无需 adToken / isplayer / check_blue**。

### 4.2 原始文件地址（可选，需要原始 mp4 时）

用第 6 节的 `/api/sharedownload`，`fid_list=["<视频fs_id>"]`，同样得到 `list[0].dlink`。

### 4.3 播放端

- m3u8 交给 **ExoPlayer HLS**（`media3-exoplayer-hls`）。
- **两种形态都要处理**：media 列表（直接有 `#EXTINF`+分片）或 master 列表（`#EXT-X-STREAM-INF`+子列表）——若遇 master 需再拉一次选定的子列表。
- 分片 URL 是**自带签名**的绝对地址（`sign=...&expires=8h`），**拉分片不需要 Cookie**，只需 `User-Agent`（建议 `pan.baidu.com`）；主列表（m3u8）需要 Cookie。

## 5. 音频取址

### 5.1 播放地址（HLS 转码流，最省事）

```
GET /mbox/msg/streaming
    ?from_uk=<from_uk>&to=<gid>&msg_id=<msg_id>&fs_id=<fs_id>&type=2
    &stream_type=M3U8_MP3_128         // ★ 音频专属档；不能填 M3U8_AUTO_480
    &clienttype=0&app_id=250528&web=1
→ 200 application/x-mpegURL  #EXTM3U ...
```

**实测（本条 mp3，8.07MB/31:33）**：`M3U8_MP3_128` → 200、214,258 字节、190 分片、`#EXT-X-ENDLIST`、无加密；分片无 Cookie 也 206 可拉。
**错误档实测**：`M3U8_AUTO_480`→400 `error_code=31304`；`M3U8_AUTO_AUDIO`→400 `error_code=31023`；`/mbox/msg/mediainfo?…&type=2`→400 `31023`（音频不需要 mediainfo）。

> 注意：`M3U8_MP3_128` 是**转码流（≈128kbps）**，体积可能比原始 mp3 还大。

### 5.2 原始文件地址（原始 mp3，更省流量）

`/api/sharedownload` → `list[0].dlink`（实测音频 sharedownload 返回 `errno:0`、`list[0].duration:1893`、含 `dlink`）。原始 mp3 只有 8MB，比转码流小，移动网络下更友好。

### 5.3 播放端

- HLS：同视频（ExoPlayer-HLS + `M3U8_MP3_128`）。
- 或原始 mp3：`sharedownload` 的 dlink 交给 `MediaItem`（`DefaultHttpDataSource`，UA=pan.baidu.com，跟随 302）。

## 6. 文档取址（只有下载这条路）

### 6.1 为什么不能用 streaming

文档无转码服务：对 PDF 调 `streaming`（两个 stream_type 都试）→ **400 `error_code=31304`**。所以文档**没有在线播放地址**。

### 6.2 唯一方法：`/api/sharedownload` → dlink

```
POST /api/sharedownload?clienttype=0&app_id=250528&web=1&sign=&timestamp=
Header: Cookie(登录态) ; Content-Type: application/x-www-form-urlencoded ; X-Requested-With: XMLHttpRequest

body (x-www-form-urlencoded)：
  encrypt=0
  uk=<viewer uk>                       // 当前账号 uk（gettemplatevariable）
  product=mbox
  primaryid=<msg_id>
  fid_list=["<fs_id>"]                 // JSON 数组，可多个：["id1","id2"]
  extra={"type":"group","gid":"<gid>"} // JSON 字符串
  timestamp=
  sign=
→ 200 {"errno":0,"list":[{"fs_id":..., "server_filename":..., "size":..., "dlink":"https://d.pcs.baidu.com/file/...&sign=..."}]}
```

**要点（实测）：**
- **`sign` / `timestamp` 留空即可**（group 文件走 mbox 体系，`errno:0`），不用逆向签名。
- 返回的 `list[0].dlink` 是**明文直链**（`https://d.pcs.baidu.com/file/<md5>?fid=<owner_uk>-250528-<fs_id>&sign=...`）。
- 用 `dlink` 下载：带 `User-Agent: pan.baidu.com` → **302** 跳到 CDN（`*.baidupcs.com/file/...&expires=8h&sta_ft=pdf`），**不需要 Cookie**（dlink 自带签名）。实测 PDF：302 → CDN，2,999,460 字节可下。
- `list[0]` 还带 `thumbs` / `docpreview` / `headurl`（文档预览缩略图相关），按需使用。

### 6.3 文档「地址」用法

- 下载/打开：直接用 `dlink`（`DefaultHttpDataSource`，UA=pan.baidu.com）。
- 在线预览：可用 `list[0].docpreview`/`thumbs`（Baidu 文档预览，非本方案主目标）。

## 7. 接口规格速查

| 接口 | 方法 | 关键参数 | 用途 | 鉴权 |
|---|---|---|---|---|
| `/api/gettemplatevariable` | GET | `fields=["uk"]` | 取 viewer uk | Cookie |
| `/imbox/file/recentv2` | GET | `session_id=04_<gid>&id=1&channel=chunlei` | 跨库最近更新列表 | Cookie |
| `/mbox/group/listshare` | GET | `gid&type=2&limit&desc=1` | 库根消息/文件列表 | Cookie |
| `/mbox/msg/shareinfo` | POST(空body) | `gid&msg_id&from_uk&fs_id&type=2&page&num&limit&desc=1` | 目录逐级下钻（只换 fs_id） | Cookie |
| `/mbox/msg/streaming` | GET | `from_uk&to&msg_id&fs_id&type=2&stream_type` | 视频/音频 HLS 播放地址 | Cookie |
| `/api/sharedownload` | POST(form) | body 见 6.2 | 原始文件 dlink（音频/视频/文档通用） | Cookie |

所有请求公共：`clienttype=0&app_id=250528&web=1` + `X-Requested-With: XMLHttpRequest` + `Referer: https://pan.baidu.com/disk/main`。

## 8. HLS 播放端要点（ExoPlayer）

1. 依赖：`androidx.media3:media3-exoplayer` + `media3-exoplayer-hls` + `media3-ui`。
2. **m3u8 主列表**：需要 Cookie。有两种拿法：
   - (推荐) 在 WebView 里同源把 `streaming` 请求下来，拿到 m3u8 正文 → 用 `ByteArrayDataSource` 喂 `HlsMediaSource`（manifest 用内存字节，避免 Cookie 问题）。
   - 或 `DefaultHttpDataSource` 配 Cookie（从 `CookieManager.getCookie("https://pan.baidu.com")` 注入）。
3. **分片**：`DefaultHttpDataSource.Factory().setUserAgent("pan.baidu.com")`（分片自带签名，不需要 Cookie）。
4. master 列表要先解析 `#EXT-X-STREAM-INF` 选一路，再拉子列表。
5. 只关画面听声音：`TrackSelectionOverride` 禁用 `TRACK_TYPE_VIDEO` + `setVideoSurface(null)`，无需转码（见项目现有 10.24 方案）。

## 9. 有效期与重取（重要）

- **m3u8 / 分片 / dlink 均约 8 小时有效**（CDN 里 `expires=8h`）。**绝不能缓存地址**：`dlink`、`streaming` 的 m3u8、`.ts`、`sharedownload` 结果都只能**播前实时取、用后即弃**。
- 失效表现：m3u8/分片 403、dlink 302 报错、`sharedownload` 报 `31360`（过期）或 `31326`（防盗链）。
- 重取策略：URL 失效 → 重新执行取址 → **用新地址 seek 回原播放位置**（记 `positionMs`，不是墙钟）。
- 列表元数据（文件名/大小/path/fs_id/msg_id）可缓存；**地址与媒体字节绝不缓存**。

## 10. 推荐实现架构（WebView 同源代发 + JS Bridge）

> 原因：接口只认 Cookie 且要同源；`sharedownload`/`streaming` 的隐藏条件由页面环境满足最稳。原生裸 HTTP 复刻会缺 Cookie、难跟接口改版。

```
[App 原生]
  ├─ 列表：WebView 内 fetch listshare/shareinfo/recentv2 → JSON 回传（JS Bridge）
  ├─ 取址：
  │   视频/音频 → WebView 内 fetch /mbox/msg/streaming(选 stream_type) → 回传 m3u8 正文
  │   文档/原始文件 → WebView 内 fetch POST /api/sharedownload → 回传 list[0].dlink
  └─ 播放/下载：
      视频/音频 HLS → ExoPlayer(HlsMediaSource：manifest=内存m3u8，分片=DefaultHttpDataSource+UA)
      音频原始/文档 → ExoPlayer/下载器(DefaultHttpDataSource：dlink，UA=pan.baidu.com，跟随302)
```

**伪代码（说明用，不是要改现有代码）：**

```text
fun resolvePlayback(entry):
    if entry.isVideo:  m3u8 = bridge.fetchStreaming(entry, "M3U8_AUTO_480"); playHls(m3u8)
    elif entry.isAudio: m3u8 = bridge.fetchStreaming(entry, "M3U8_MP3_128");  playHls(m3u8)
    else:               // 文档
        dlink = bridge.sharedownload(entry).list[0].dlink; openFile(dlink)

fun resolveOriginal(entry):  // 音视频要原始文件时
    dlink = bridge.sharedownload(entry).list[0].dlink; playOrDownload(dlink)
```

- `bridge.fetchStreaming` = 在网盘 WebView 里同源 `GET /mbox/msg/streaming?...`，返回 `responseText`（m3u8）。
- `bridge.sharedownload` = 在网盘 WebView 里同源 `POST /api/sharedownload`，返回解析后的 JSON。
- 这套与项目现有 `PanApi` + `MainActivity.load()` + `VideoStreamResolver` 的「WebView 代发」思路一致，可直接复用其桥接机制。

## 12. 错误码速查

| errno / error_code | 含义 | 处理 |
|---|---|---|
| `errno:-6` | 未登录 / Cookie 失效 | 重新登录；确保同源带 Cookie |
| `error_code:31304` | 该类型/档位不可转码（如给音频配视频档、给文档配任何档） | 换正确 `stream_type`；文档改走 sharedownload |
| `error_code:31023` | 参数错误（档名不存在/参数缺失） | 检查 `stream_type` 与必填参数 |
| `errno:0` | 成功 | — |
| （dlink）`31326` / `31360` / `31045` | 防盗链 / 过期 / token 失效 | 重新 `sharedownload` 取新 dlink |
| （分片/m3u8）403 | 地址过期（>8h） | 重新 `streaming` 取新 m3u8 |

## 13. 踩坑清单（开发必读）

1. **别把 `pfile/mboxvideo` 当地址**——它是 HTML 播放器页，新标签打开，拿不到流。
2. **`to` 就是库 `gid`**（同一 17 位值），不存在单独的「19 位 to」；19 位的是 `msg_id`。
3. **`#/im/session?fromId=` 的 `fromId` = viewer uk**（自己的账号），不是文件/库 ID。
4. **`stream_type` 必须按类型选**：视频 `M3U8_AUTO_480`，音频 `M3U8_MP3_128`，填错 → 31304/31023。
5. **文档不能 streaming**，只走 `sharedownload`。
6. **列表 `recentv2` 的 `meta.dlink` 是加密串（base64，非 URL）**——不要直接用；要明文直链就用 `sharedownload` 返回的 `list[0].dlink`。
7. **`sharedownload` 的 `sign`/`timestamp` 留空即可**（group 场景），别去逆向签名。
8. **m3u8 主列表需 Cookie，分片不需要**；分片需 `User-Agent: pan.baidu.com`。
9. **地址 8 小时过期，绝不缓存**；缓存元数据可以，缓存地址会 403。
10. **`uk`（body 里）用 viewer uk（自己），不是 from_uk（分享者）**——两个别填反。
11. m3u8 可能是 **master**（要选子列表）也可能是 **media**（直接分片），两种都要判。

## 14. 验收 / 负面测试

- 视频：`M3U8_AUTO_480` 出 m3u8 → ExoPlayer 播 10 分钟、seek、切清晰度各一次。
- 音频：`M3U8_MP3_128` 出 m3u8 → 播完一条；再测 `sharedownload` 原始 mp3 可播。
- 文档：`sharedownload` 出 dlink → 302 下载完整（PDF 2.9MB 校验大小）、能打开。
- 负面：未登录 → `errno -6` 有明确提示；地址过期（>8h）→ 自动重取并 seek 回原位；给音频配视频档 → 提示不支持；给文档调 streaming → 提示不可播改下载；跨库/目录下钻 fs_id 失效 → 提示重选不崩。
- 频控：连续下钻/取址之间加间隔（官方 listall 频控 31034 ≤8~10 次/分），不要并发轰炸。
