# 百度网盘 / 夸克网盘 上传接口与大小权限分析

> 目的：搞清两家的**上传接口**（网页版内部接口 / 开放平台接口）、**单文件大小与分片权限**，以及**上传大文件更好的做法**。
> 证据来源：① 实测真机 `emulator-5554` 上 App 的 WebView 会话直连接口；② 百度网页版前端 JS（`nd-static.bdstatic.com/m-static/v20-main/home/js/chunk-*.js`，上传模块）反查；③ 百度开放平台官方文档；④ 夸克接口实测（Cookie 从 App 导出，用后即删）+ 社区逆向文档。
> 文中 `bdstoken` / `uk` / `cookie` 一律不记录真实值。

---

## 0. 结论速览

| 项目 | 百度网盘 | 夸克网盘 |
|---|---|---|
| 网页内部接口 | `POST /api/precreate?` → `POST /rest/2.0/pcs/superfile2?method=upload` → `POST /api/create?isdir=0`（bdstoken） | `POST /file/upload/pre` → `POST /file/upload/auth` → `PUT {bucket}.pds.quark.cn/...`（分片）→ `POST 完成合并(XML)` → `POST /file/upload/finish` |
| 开放平台接口 | `/rest/2.0/xpan/file?method=precreate` + `superfile2` + `?method=create`（access_token） | —（无公开开放平台上传） |
| 分片大小 | 普通 **4MB 固定**；会员 ≤16MB；超级会员 ≤32MB | **<5MB 单分片；≥5MB 按 4MB 分片** |
| 单文件上限（官方口径） | 普通 **4GB**、会员 **10GB**、超级会员 **20GB**；分片数 ≤**1024** | 实测本号(SUPER_VIP) **≤100GB**（100GB ok，101GB 报 `32004 file is too big`） |
| 单步上传（不走分片） | ≤**2GB** | — |
| 秒传 | `/api/rapidupload?`（文件 >**256KB** 先算 MD5 再试秒传） | `file/update/hash`（`ccp_hash_update`，md5/sha1） |
| 关键权限 | 账号等级决定单文件/分片大小；空间不足、违规内容会被拒 | 会员等级 + 空间；单文件 100GB 上限 |

> 一句话：**两家都支持"分片 + 秒传"，大文件的正确姿势是"先算哈希试秒传 → 不中再按 4MB 分片并发上传 → 最后 create/finish 合并"**；真正卡人的不是接口，而是**账号等级对应的单文件上限**和**空间/风控**。

## 1. 百度网盘

### 1.1 网页版内部上传链路（本 App 这类"网页会话"用的就是这套）

从网页版前端 JS 反查到的上传器配置（原文节选）：

```js
// chunk-*.js（uploader 模块）
conf = { chunkSize: 4194304, file_rapid_min_size: 262144, ... }   // 4MB 分片；>256KB 尝试秒传
options = {
  preCreateUrl : "/api/precreate?",
  superFileUrl : "/rest/2.0/pcs/superfile2?method=upload",
  createUrl    : "/api/create?isdir=0",
  rapidUploadUrl: "/api/rapidupload?",
  locateUploadUrl: "/rest/2.0/pcs/file?method=locateupload",
  extParams: { app_id:250528, channel:"chunlei", web:1, clienttype:0 },
  accessParam: "bdstoken=" + bdstoken
}
```

流程（三步 + 秒传分支）：

```
① 预上传  POST /api/precreate?channel=chunlei&web=1&app_id=250528&clienttype=0&bdstoken=<TOKEN>
   form: path=/xxx.bin, size=<字节>, autoinit=1,
         block_list=["<4MB分片MD5>", ...]    // 关键：分片 MD5 数组，长度=ceil(size/4MB)
   → { errno:0, uploadid:"...", return_type:1, block_list:[需要上传的分片序号...] }

② 分片上传 POST /rest/2.0/pcs/superfile2?method=upload&type=tmpfile&channel=chunlei&web=1&app_id=250528&bdstoken=<TOKEN>
   form(multipart): path=..., uploadid=..., partseq=<序号>, file=<该 4MB 分片二进制>
   （≤4MB 的文件只传 partseq=0 一次）

③ 创建文件 POST /api/create?isdir=0&channel=chunlei&web=1&app_id=250528&bdstoken=<TOKEN>
   form: path, size, isdir=0, uploadid, block_list=["<各分片上传返回的MD5>",...], rtype=1
   → errno 0 即落盘

（秒传）POST /api/rapidupload?   form: path,size,content-md5,slice-md5,target_path
   → 服务端已有同 MD5 文件时直接成功，无需上传
```

要点：
- **`block_list` 的长度必须等于 `ceil(size / 4MB)`**，且是每片 4MB 的 MD5（最后一片不足 4MB 按实际）；`precreate` 用它判断哪些分片真正需要上传（秒传/复用）。
- 返回的 `return_type`：`1` 普通上传；命中秒传/全已存在时表现为无需再传。
- `rtype`：冲突策略，`1` 重命名 / `2` 分片不同时重命名 / `3` 覆盖。
- `locateupload`（`d.pcs.baidu.com/rest/2.0/pcs/file?method=locateupload`）用于**定位/复用已上传的分片**（跨文件秒传、断点续传的底层）。
- 上传域名需用「获取上传域名」动态取（`d.pcs.baidu.com`），HTTPS 优先。

### 1.2 官方开放平台接口（OAuth access_token，等价能力、有明确文档限制）

- 预上传 `POST /rest/2.0/xpan/file?method=precreate`
- 分片上传 `POST https://<UPLOAD_HOST>/rest/2.0/pcs/superfile2?method=upload&type=tmpfile`（multipart，`partseq` 从 0）
- 创建文件 `POST /rest/2.0/xpan/file?method=create&isdir=0`
- 单步上传（≤2GB）
- 获取上传域名 `GET https://d.pcs.baidu.com/rest/2.0/pcs/file?method=locateupload`

### 1.3 大小 / 权限（官方文档口径，更新于 2026-09-09）

| 用户身份 | 单文件上限 | 单分片大小 |
|---|---|---|
| 普通用户 | **4 GB** | **固定 4 MB** |
| 会员 | **10 GB** | ≤16 MB |
| 超级会员 | **20 GB** | ≤32 MB |

- **分片数量不得超过 1024 个**（所以 4MB×1024≈4GB 正好卡住普通用户；要传更大必须用更大分片，而分片变大又要求会员等级）。
- **单步上传（不走分片）上限 2GB**，更大文件或需稳定续传必须用分片流程。
- 文件 ≤4MB：`block_list` 只放整体 MD5，单分片一次传完；>4MB：本地切分按序提交每片 MD5。
- 类型/目录限制：普通用户上传落到 `/apps/{appname}`（应用数据目录），违规文件、空间不足会被拒。

### 1.4 本次实测（真机 WebView 会话，账号 `is_vip:0` 普通用户）

| 测试 | 结果 |
|---|---|
| `precreate` size=4MB，block_list=1 个 MD5 | **errno 0**，返回 `uploadid`、`return_type:1`、`block_list:[0]` |
| `precreate` size=8MB，block_list=2 个 MD5 | **errno 0**，`block_list:[0,1]` |
| `precreate` block_list=[]（空） | **errno 2**（参数错误：分片数必须与 size 匹配） |
| `precreate` size=4GB/20GB/50GB/100GB/101GB/200GB（block_list 按 4MB 补齐） | **全部 errno 0**（说明 precreate 接口本身不校验大小，真正的上限在账号等级/`create` 与服务端） |
| 走 `xpan` 预上传（误用无 access_token） | `errno 9019 "need verify"`（风控；网页内部接口不要混用开放平台签名） |

> 结论：**网页内部 `precreate` 不在预上传阶段拦大小**（200GB 也返回 0），真实可用大小取决于账号等级（官方 4/10/20GB）、空间与 `create` 阶段；实测账号是非会员，按官方口径单文件应 ≤4GB。

### 1.5 秒传

- 文件 **>256KB** 时先算整文件 MD5（及分片 MD5），调 `/api/rapidupload?`；命中则**零字节秒传**。
- 秒传/分片复用底层是 `locateupload`：服务端已有相同 block 时 `precreate` 的 `block_list` 不包含该分片序号，直接跳过上传。

## 2. 夸克网盘

### 2.1 上传链路（分片直传阿里云 OSS）

```
① 预上传   POST https://drive-pc.quark.cn/1/clouddrive/file/upload/pre?pr=ucpro&fr=pc
   body(JSON): { ccp_hash_update:true, parallel_upload:true, pdir_fid:"<目录>", dir_name:"",
                 size:<字节>, file_name:"x.bin", format_type:"mime",
                 l_updated_at:<ms>, l_created_at:<ms> }
   → data: { task_id, finish, upload_id, obj_key, upload_url:"http://pds.quark.cn",
             fid, bucket:"ul-zb", callback, format_type, size, auth_info, auth_info_expried, file_struct }

② 秒传哈希(可选) POST /1/clouddrive/file/update/hash   body:{ task_id, md5, sha1 }
   （ccp_hash_update=true 时；命中则 finish=true，无需上传）

③ 取上传授权 POST /1/clouddrive/file/upload/auth  body:{ task_id, auth_info, auth_meta }
   → data.auth_key（作为 PUT 的 Authorization 头）

④ 分片上传  PUT https://{bucket}.pds.quark.cn/{obj_key}?partNumber={N}&uploadId={ID}
   header: Content-Type, x-oss-date, x-oss-user-agent, authorization=auth_key,
           X-Oss-Hash-Ctx:<分片2+的增量SHA1上下文>
   → 200，ETag 为分片标识

⑤ 完成合并  POST https://{bucket}.pds.quark.cn/{obj_key}?uploadId={ID}
   header: Content-Type: application/xml, x-oss-callback, Content-MD5, authorization
   body: <CompleteMultipartUpload><Part><PartNumber>1</PartNumber><ETag>"..."</ETag></Part>...</CompleteMultipartUpload>

⑥ 通知完成  POST /1/clouddrive/file/upload/finish  body:{ task_id, obj_key }
```

- **分片策略**：`<5MB` 单分片；`>=5MB` 多分片，**每片 4MB**。
- `fid` 在预上传阶段就返回（目标占位 fid），`finish:false` 表示还需上传；`auth_info` 是 OSS 临时凭证（base64），有有效期（`auth_info_expried`），过期需重新 `pre`。

### 2.2 本次实测（真机导出的 Cookie，账号 `SUPER_VIP`，容量 6.6TB/已用 3.4TB）

`POST /file/upload/pre` 各大小结果：

| 文件大小 | 结果 |
|---|---|
| 1MB / 5MB / 10MB | `code:0`，返回 `task_id/upload_id/obj_key/upload_url/fid/bucket/auth_info` |
| 1GB | `code:0`（bucket 切到 `ul-zb`） |
| 20GB | `code:0` |
| **100GB** | **`code:0`（允许）** |
| **101GB** | **HTTP400 `code:32004`，`message:"file is too big[{0}]"`** |
| 105/109GB | 同样 `32004` |

→ **夸克单文件上传上限实测 = 100GB**（至少 SUPER_VIP 账号如此）；非会员上限更低（未换账号实测）。

### 2.3 秒传

- `file/upload/pre` 的 `ccp_hash_update:true` + `POST /file/update/hash {task_id,md5,sha1}`；服务端已有相同文件时直接 `finish:true`，跳过 OSS 上传。
- 分片 2 片起需要 `X-Oss-Hash-Ctx`（OSS 增量 SHA1 上下文），否则合并校验会失败。

## 3. 两家对比 & "更好的上传大文件方法"

### 3.1 通用最佳实践

1. **先秒传后上传**：先算整文件 MD5/SHA1 → 试秒传；命中则 0 流量。对大文件/常见资源收益最大。
2. **分片 + 并发 + 断点续传**：4MB 分片，3–5 并发；记录每个分片 ETag/序号，失败只重传该片；续传靠 `precreate` 返回的"仍需上传分片序号"（百度）或 task_id+obj_key+已传 partNumber（夸克）。
3. **流式读文件，不要整包进内存**：按 4MB `RandomAccessFile` 切片读；`HmacSHA1/MD5` 增量计算；WebView `fetch` 只适合小文件（CORS + 内存 + 无法流式）。
4. **用官方/开放平台 API，不要用网页内部 bdstoken 接口做长期方案**：网页接口无文档、易触发风控（实测百度 xpan 误用直接 `9019 need verify`）。
5. **提升账号等级**：百度普通 4GB→会员 10GB→超级会员 20GB（分片也从 4MB→16MB→32MB）；夸克 SVIP 可达 100GB。
6. **超上限就拆包**：>20GB(百度)/>100GB(夸克) 用分卷压缩（如 4GB/卷）分别上传，或先传到别处再"转存/分享"。

### 3.2 给本 App 的实现配方（若要加"上传"能力）

**百度（网页会话 bdstoken 版）**
```
1) fetch /api/gettemplatevariable?fields=["bdstoken"] 取 bdstoken
2) 读文件 → 按 4MB 切 → 逐片 MD5 组成 block_list
3) POST /api/precreate?bdstoken=... (path,size,autoinit=1,block_list,target_path)
4) 对返回 block_list 里的每个 partseq：POST /rest/2.0/pcs/superfile2?method=upload
   （multipart: path,uploadid,partseq,file=该片）；并发 3–5
5) POST /api/create?isdir=0 (path,size,isdir=0,uploadid,block_list=<各片返回MD5>,rtype=1)
※ 先试 /api/rapidupload（md5）可省流量；注意普通账号 ≤4GB、分片 4MB、分片数≤1024
```

**夸克（分片直传 OSS）**
```
1) POST /file/upload/pre {file_name,size,pdir_fid,format_type,ccp_hash_update:true,...}
   → task_id / upload_id / obj_key / bucket / auth_info
2) (可选) POST /file/update/hash {task_id,md5,sha1} → finish=true 则秒传完成
3) POST /file/upload/auth {task_id,auth_info,auth_meta} → auth_key
4) PUT https://{bucket}.pds.quark.cn/{obj_key}?partNumber=N&uploadId=... （4MB/片，并发 3–5，
   第2片起带 X-Oss-Hash-Ctx）
5) POST https://{bucket}.pds.quark.cn/{obj_key}?uploadId=... （CompleteMultipartUpload XML）
6) POST /file/upload/finish {task_id,obj_key}
※ 单文件 ≤100GB（SVIP），分片 <5MB 单片 / ≥5MB 按 4MB
```

### 3.3 大小/权限速查

| | 百度 普通 | 百度 会员 | 百度 超会 | 夸克（SVIP 实测） |
|---|---|---|---|---|
| 单文件上限 | 4 GB | 10 GB | 20 GB | **100 GB** |
| 分片大小 | 4 MB | ≤16 MB | ≤32 MB | 4 MB（≥5MB 文件） |
| 分片数上限 | 1024 | 1024 | 1024 | 未观测到硬上限 |
| 单步上传 | ≤2 GB | ≤2 GB | ≤2 GB | — |

## 4. 权限 / 风控注意

- 百度：`precreate` 只校验 `block_list` 与 `size` 是否自洽（不匹配 → `errno 2`）；`xpan` 与网页 `bdstoken` 两套签名**不能混用**（混用 → `9019 need verify`）。违规内容/空间不足会在 `create` 或上传阶段失败。
- 夸克：`file is too big` = `32004`（超单文件上限）；`401/403` = Cookie 失效/访问被拒；`capacity limit` = 空间不足；`20002` = 账号失效。
- 上传 OSS 的 `auth_info` 有时效；大文件分片耗时超过有效期需重新 `pre` 续期。
