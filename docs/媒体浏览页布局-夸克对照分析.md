# 媒体浏览页布局对照分析（夸克 vs 本应用）

> 范围：只看**布局结构**，不含视觉皮肤、动效、业务逻辑。样本为夸克网盘 6 张截图（视频横屏 / 竖屏详情 / 音频 / 文件列表 / 图片浏览），对照本应用 `VideoPlaybackPage.kt`、`MainActivity.kt`（音频页）、`ImageViewerActivity.kt` 的现有实现。

## 0. 结论

夸克"好看"不是靠装饰，而是三类媒体页共用**同一套四层骨架**：

| 层 | 做法 | 作用 |
|---|---|---|
| L0 内容层 | 图片/视频**全出血**顶到状态栏下面，edge-to-edge | 沉浸感，没有"框" |
| L1 顶栏 | 高 44–52dp，**透明或渐变**，左返回 + **居中两行标题**（主 15–16sp / 副 11–12sp 灰）+ 右侧最多 2 个动作，其余收进 `···` | 信息分层，不抢画面 |
| L2 浮层胶囊 | 圆角胶囊贴着内容浮（"原图 600.2KB"、"上次观看至 00:21 已为您自动续播"） | 提示不占版面 |
| L3 底部动作栏 | **图标 24dp + 标签 11sp 等分网格**，5–6 格（分享/修图/横屏/收藏/下载/删除） | 动作可读、可发现 |
| L4 播放条 | `时间 — 细轨道(2dp)+圆点 — 时间` 同一条水平线 | 轻、不压画面 |

我们的问题不在配色，而在**每个页面各自造了一套 chrome**：视频页把"浏览页的实色顶栏"搬进播放器、图片页用文字按钮代替动作栏、音频页把封面缩成缩略图。三者拼在一起就显得散、显得丑。

## 1. 分页对照

## 2. 我们"丑"的 5 个结构性根因

1. **顶栏是实色块，而不是浮层**。视频页为此还把内容整体下推 52dp，直接制造黑边。
2. **控制层级错位**：该在底部的（选集、倍速、上一集/下一集）跑到画面中央做成胶囊；该在顶部收起的（定时/收藏/纯音频）摊成 4 个无标签图标。
3. **缺少"图标 + 文字"的动作栏**。三页全部依赖纯图标或文字按钮，可发现性差，也没有统一的落点。
4. **音频页没有视觉主体**。68dp 封面 + 控制卡片 + 常驻列表，三块等权重垂直堆叠。
5. **列表行没有视觉锚点**。选集/课程列表是纯文字 + 底色块，缺缩略图与状态徽标（已观看/时长/清晰度）。

### P2 — 精细

- 进度条统一为 2dp 轨道 + 8dp 圆点，时间与轨道同一行（三页一致）。
- 浮层胶囊：`原图 600.2KB`、`上次观看至 00:21 已为您自动续播`。
- 图片页顶部标题的两行字号关系固定为 15sp / 11sp。

## 4. 成本与风险

- 三个页面都是**程序化 UI**（Kotlin 直接 new View），布局改动集中在构造方法内，除 `video_player.xml` 的 `videoActions` 容器外没有 XML 依赖，改动面可控。
- 真正的难点是**沉浸式**：`updateSystemBars()` 与 `gestureLayer` 已存在，顶栏透明化后要保证 scrim 与 insets 一致，否则亮画面下白字不可读。
- **缩略图列表不属于纯布局**：需要额外取址与缓存，`ImagePreviewLoader` / `ImageCache` 可复用，但要单独评估接口成本。

## 5. 建议顺序

1. **图片浏览**（P0-3）：改动最小、收益最直观，先把"动作栏"这套语言立起来。
2. **视频横屏**（P0-1 + P0-2）：去掉黑边、拆胶囊，观感提升最大。
3. **音频页**（P1-2）：从"列表页"变"播放页"。
4. **选集列表缩略图**（P1-3）：需要接口配合，单独排期。
