# 媒体页统一设计规范（视频 / 音频 / 图片）

> 目的：三页共用一套骨架，避免各自造 chrome。
> 配套原型：`docs/媒体页统一骨架-原型.html`（可点击，含状态切换与倍速菜单）。

---

## 一、四槽骨架

```
┌──────────────────────────────────┐
│  A  导航槽            52dp        │  返回/收起 + 标题(1~2 行) + ≤2 动作 + ···
├──────────────────────────────────┤
│                                  │
│  B  内容槽            flex        │  视频:画面  音频:封面+标题  图片:图片
│                     (底部浮传输组) │
│                                  │
├──────────────────────────────────┤
│  C  进度槽            40dp        │  时间 — 轨道 — 时间
├──────────────────────────────────┤
│  D  动作槽            66dp        │  视频 6 格 / 音频·图片 5 格
└──────────────────────────────────┘                 图标 21 + 标签 10.5sp
```

三页只在 B 槽与 D 槽的动作集合上不同，A/C 槽完全一致。
D 槽格数：视频竖屏 6 格（多一格「转音频」），视频横屏 5 格，音频 5 格，图片 5 格。

## 二、规则

| 编号 | 规则 | 解决的原问题 |
|---|---|---|
| R1 | 一页四槽，槽高/字号/间距/颜色全局固定 | 三页各造一套布局 |
| R2 | 视频与音频的 D 槽**共有五项同序**：`选集 · 倍速 · 收藏 · 定时 · 更多`；视频在此之外多一格「转音频」，音频不设该格 | 音频与视频体验割裂 |
| R3 | 倍速**只作为 D 槽一格**，标签直接显示当前值；不再以文字按钮混入传输组 | 动作行 7 项、播放键偏左 50dp |
| R4 | 传输组固定三件（上一 / 播放 / 下一），56dp 圆钮居中，浮在 B 槽底部，不与进度条同排、不参与权重分配 | 中央胶囊组压画面、对称破坏 |
| R5 | 主标题全局只出现一次：视频在 A；音频在 B（封面下方）；图片在 A（两行） | 标题重复或信息缺失 |
| R6 | 显隐状态机：视频竖屏收 C+D 保留 A；横屏全收；音频常驻；图片单击收 A+D | chrome 常驻压画面 |
| R7 | 低频动作只能落 D 槽或 A 槽 `···`；A 槽右侧硬上限 2 个图标 | 顶部 4 个无标签图标 |
| R8 | 所有可点元素最小热区 44×44；图标线宽 1.7 | 误触与不可点感 |
| R9 | 横屏走**叠加模式**：A/C/D 全部浮在画面上，画面 100% 铺满，不沿用竖屏的纵向排布 | 横屏控件吃画面 |
| R10 | 横屏传输组**并入进度行左端**（上一 · 播放 · 下一 + 时间 + 轨道 + 时长），D 槽保持不变 | 横屏没有垂直空间放浮层传输组 |
| R11 | **「转音频」只给竖屏视频页**，固定紧跟「倍速」右侧（第 3 格）；音频页与**横屏**都是 5 格，不设该格、不留空位 | 只有竖屏看视频时才需要“收起画面只听” |

| A 导航 | 52dp（不含状态栏） | 左右 6dp | 主 14sp medium / 副 11sp | 标题 `#F2F3F7` / 副 `#8E909C`；底为顶部渐变 scrim `rgba(10,11,14,.92) → 0` |
| B 内容 | flex | 视频 0；音频 左右 28dp | 音频封面标题 17sp / 来源 11.5sp | 来源 `#8E909C` |

| D 动作 | 66dp | 视频竖屏 6 格 / 其余（视频横屏、音频、图片）5 格 | 标签 10.5sp | 默认 `#8E909C` / 选中 `#BFC6FF` / 收藏 `#FFC857` |

## 四、显隐状态机

| 页面 | 默认态 | 单击画面 | 自动收起 | 例外 |
|---|---|---|---|---|
| 视频·竖屏 | A 可见，C/D 隐藏 | 显/隐 C+D | 3s | A 不隐藏（Dialog 无返回入口） |
| 视频·横屏 | 全隐藏 | 显/隐 A+C+D | 3s | 锁定后点击不再响应 |
| 音频 | A/C/D 常驻 | 不响应 | 不收起 | 音频需要可见进度与控制 |
| 图片 | A/D 可见 | 显/隐 A+D+胶囊 | 不自动 | 默认就要能看到翻页与动作 |

## 五、两种布局模式（竖屏 / 横屏）

| 维度 | 竖屏 | 横屏 |
|---|---|---|
| 布局模式 | 四槽**纵向排布**，画面被上下压缩 | 四槽**叠加**，画面 100% 铺满 |
| A 槽 | 52dp，实位占高 | 48dp，浮在画面上，顶部 scrim 88dp |
| C 槽 | 40dp | 36dp，并入底部叠加区 |
| D 槽 | 66dp，6 格 | 56dp，**5 格（不设「转音频」）**，叠在底部 scrim 上 |
| 传输组 | 浮在 B 槽底部居中 | 并入 C 槽左端：`‹ ▶ ›` + 时间 + 轨道 + 时长 |
| 图标 | A 24 / D 21 | A 22 / D 19 |
| 标签 | 10.5sp | 10sp |
| 默认态 | A 可见，C/D 隐藏 | A/C/D 全隐 |
| 自动收起 | 3s | 3s（锁定后不响应） |
| 底部 scrim | 无（D 槽自身带底色） | `rgba(10,11,14,.94) → 0`，高度约 120dp |

横屏的关键约束：**不新增控件**，只把传输组从"浮层三件"改成"进度行左端三件"，保证同一套图标与顺序在两种方向下都成立。
唯一的方向差异：横屏**去掉「转音频」格**（5 格）。因为转入横屏就是为了看满屏画面，而"转音频"的语义恰好是收起画面，两者互斥；横屏又只有 334dp 高，不该再分一格给它。

## 六、三页动作集合

| 页面 | D 槽动作（固定顺序） | 格数 | A 槽右侧 |
|---|---|---|---|
| 视频（竖屏） | 选集 · 倍速 · **转音频** · 收藏 · 定时 · 更多 | 6 | 全屏、`···` |
| 视频（横屏） | 选集 · 倍速 · 收藏 · 定时 · 更多（**无转音频**） | 5 | 退出全屏、`···` |
| 音频 | 选集 · 倍速 · 收藏 · 定时 · 更多 | 5 | `···` |
| 图片 | 原图 · 上一张 · 下一张 · 收藏 · 更多 | 5 | `···` |

`···` 菜单内容：视频/音频 = 投屏（暂无）、下载（暂无）、文件信息；图片 = 用其他应用打开、保存、文件信息。
（原「只听声音」已从 `···` / 顶栏移出，独立成为视频页 D 槽的「转音频」格。）

### 6.1 「转音频」为什么只有视频有

音频页播放的本来就是音频流，不存在"再转一次"的语义；把它也放上会让音频页出现一个点了没反应的格子，破坏整套骨架的可信度。因此规则是：**需要改变媒体形态的页面才有这一格**。

| 项 | 约定 |
|---|---|
| 位置 | 紧跟「倍速」右侧，固定为**竖屏**视频 D 槽第 3 格 |
| 默认标签 | `转音频`（耳机图标） |
| 激活标签 | `音频中` + `#BFC6FF` 高亮，与「收藏 / 已收藏」同一套状态表达 |
| 激活后 B 槽 | 画面收起，换为音频态：148dp 圆形字形 + `正在以音频模式播放` + `画面已收起 · 可后退或切到后台继续听` |
| 再次点击 | 回到画面，标签复原为 `转音频` |
| 横屏 | **不出现**，D 槽 5 等分（转音频 = 收起画面，与横屏看满屏互斥） |
| 音频页 | **不出现、也不留空位**，仍是 5 等分 |

### 6.2 三种落地路径（按成本排序）

| 路径 | 做法 | 是否省流量 | 成本 |
|---|---|---|---|
| A 只关视频轨（现状可复用） | `player.trackSelectionParameters.setTrackTypeDisabled(TRACK_TYPE_VIDEO, true)`，即现有 `listening` 逻辑（`VideoPlaybackPage.kt:104、171-190`） | ❌ 仍拉 480p 视频分片 | 最低，改按钮位置与文案即可 |
| B 换音频流 | 用同一个 `fs_id` 重新取址到 `M3U8_MP3_128`（`PanApi.diskAudioPlaylist`），替换 `MediaSource` | ✅ 约 128kbps | 中：需重新取址、换源、处理续播位置 |
| C 导出音频文件 | 服务端转码任务产出 mp3，再下载/保存到网盘或本地 | ✅ | 高：需服务端能力，本期不做 |

**建议**：先按 A 落地（视觉与交互先行），路径 B 作为"真正省流量"的后续单独立项——因为用户点「转音频」的动机多半是省流量或后台听，而 A 并不省流量，这一点必须在文案上诚实（`画面已收起`，不写"省流量"）。

## 八、与夸克的取舍

| 夸克有 | 是否采用 | 原因 |
|---|---|---|
| 控制层自动隐藏 | ✅ 采用（视频） | 我们目前常驻，是"丑"的主因 |
| 透明顶栏 + 两行标题 | ✅ 采用（图片） | 视频/音频标题位置不同，规则见 R5 |
| 底部 icon+label 动作栏 | ✅ 采用 | 我们缺这套语言 |
| 播放键与进度同排 | ❌ 不采用 | 与音频难以统一；改为 B 槽底部三件组，视频音频同构 |
| 竖屏详情页（Tab + 选集列表） | ⏸ 暂缓 | 需把 Dialog 改成页面栈，单独评估 |
| AI 总结 / 文稿 Tab | ❌ 不做 | 无对应能力 |
| 锁屏键 | ⏸ 可选 | 横屏误触确实存在，优先级低 |
| 转文字 / 修图 / 投屏 | ❌ 不做 | 无对应能力 |
| ——（夸克无此按钮，靠后台播放代替） | ➕ 我方新增 | 训练类视频常被当音频听，显式给一格比藏在菜单里可靠 |

## 九、验收清单

- [ ] 三页 A 槽高度均为 52dp，标题与图标的基线一致
- [ ] 视频/音频 D 槽五个共有动作、顺序、间距完全一致
- [ ] 「转音频」只出现在**竖屏视频** D 槽第 3 格（紧跟倍速）；横屏与音频页均为 5 格，无空位、无灰格
- [ ] 竖屏 → 横屏切换时「转音频」格消失，转回竖屏时状态不丢（若当时在音频态，回竖屏继续音频态）
- [ ] 转音频激活后 B 槽切为音频态，标签变「音频中」并高亮；再次点击复原画面
- [ ] 转音频状态下切集、旋屏、退到后台，音频会话不中断也不重复启动
- [ ] 播放键在任意屏宽下都位于容器水平中心（误差 0）
- [ ] 倍速标签与当前播放速度实时同步，弹菜单不打断播放
- [ ] 视频竖屏点击一次收起 C+D、再点恢复；横屏全收
- [ ] 返回入口在任意显隐状态下都可点
- [ ] 图片页单张时不出现上一张/下一张（或置灰）
- [ ] 横屏画面铺满无黑边，A/C/D 全部浮在画面上（不占位）
- [ ] 横屏传输组在进度行左端，与竖屏的浮层组图标一致、顺序一致
- [ ] 横屏转入竖屏时，控制层状态不闪烁、不遗留半透明残影

## 十、落地状态（2026-11-11 实机）

| 项 | 规范 | 实际实现 | 说明 |
|---|---|---|---|
| 音频 B 槽封面 | 236dp | **200dp** | 1080×2400 上 236dp 会挤压标题与传输组，实测 200dp 居中比例更稳 |
| 音频传输组 | 浮在 B 槽底部 | **跟在标题下方，作为 B 槽内容块整体居中** | 浮底会在课程列表弹层/布局变化时与文字拉开或重叠 |
| 音频「选集」 | 抽屉上滑 | **AlertDialog 弹层**（与视频页 courseButton 一致） | 主列表始终常驻，布局占位不变，不产生空白块 |
| 音频 ±30 秒 | 未定义 | **长按上一/下一** + 「更多」菜单两项 | 传输组固定三件才能严格对称；功能不丢 |
| 视频竖屏 D 槽 | 6 格 | **4 格**：`0.75x · 转音频 · 收藏 · 定时` | 「选集」因课程列表常驻被隐藏，「更多」菜单待做 |
| 视频顶栏 | 透明渐变 | 仍为实色 `0xD9111118` | 待做；需同步 scrim 保证亮画面下白字可读 |

视频页控制层收起时，`stageHeight` 不再预留 120dp，课程列表上移填补，画面保持 16:9 不变——已消除"隐藏后中间空白"。音频页控制条常驻，不存在该问题。
