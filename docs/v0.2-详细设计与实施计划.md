# 拾课 v0.2「效率补全」详细设计与实施计划

- 版本基线：0.1.23（`versionCode 24`，分支 `main`）
- 目标版本：0.2.0（`versionCode 25`）
- 文档性质：只做设计，不改源码；评审通过后再按本文落地
- 关联文档：[功能扩展规划.md](功能扩展规划.md)

## 0. 版本目标与边界

### 0.1 本版目标
在不动现有取流/播放架构的前提下，补齐「找得快、选得多、听得安心、知道听没听、换号方便」五件事，把日常使用摩擦降到最低。

### 0.2 纳入范围（5 项）
| # | 功能 | 一句话价值 | 估时 |
|---|---|---|---|
| V02-1 | 全局搜索 | 记不住课在哪个群，也能一次搜到 | 2.5 人天 |
| V02-2 | 批量操作 | 整门课批量收藏/取消收藏，不用逐条点 | 2 人天 |
| V02-3 | 睡眠定时 | 听课程入睡自动停，可「本集结束停」 | 1.5 人天 |
| V02-4 | 未听/未完成筛选 | 一键筛出没听完的课 | 1 人天 |
| V02-5 | 多账号快速切换 | 账号档案 + 一键登出重登，本地数据按号隔离 | 2 人天 |
| — | 联调/回归 | 全链路回归 + 平板/深色 | 1 人天 |
| — | 合计 | — | ≈ 10 人天（单人约 2 周） |

### 0.3 明确不做（留到后续版本）
- 批量离线下载、自建播放列表/课程包 → v0.4
- 视频 AI 总结/字幕/笔记 → v0.3
- 网盘上传/重命名/删除/转存 → v0.5
- 真正的「多账号同时在线」：受 `CookieManager` 全局单实例限制，本版只做「账号档案 + 快速重登」（见 V02-5 说明）

### 0.4 建议实施顺序
`V02-1 全局搜索 → V02-4 未听筛选 → V02-2 批量操作 → V02-3 睡眠定时 → V02-5 多账号`
理由：搜索与筛选是纯读取，风险最低；批量为 UI 重构，需要先稳定筛选状态栏；睡眠定时碰播放服务；多账号碰登录态，放最后统一回归。

## 2. V02-1 全局搜索

### 2.1 问题
现在搜索范围二选一：当前群（`searchFiles`）或我的网盘（`searchDiskFiles`），用户不记得课程在哪个来源时无法一次命中。

### 2.2 交互设计
1. 搜索弹窗（`dialog_search_input.xml`）在输入框下方增加「范围」三选一：
   - `我的网盘`（默认）：只搜个人网盘；
   - `群组`：只搜**所有已关联群组的文件库**，不搜个人网盘；
   - `全部`：群组 + 我的网盘一起搜。
   > 默认用「我的网盘」：多数人先在已转存的网盘里找，范围最小、返回最快；需要找群文件库时切「群组」，要一次全找再选「全部」。范围选择记住上次使用（`app_settings` 存 `search_scope`）。
2. 数据量控制（用户明确提到「可能数据很多」）：
   - 结果按来源分组，标题下显示 `已搜 2/5 群 · 128 项`，每个群里最多取 800 条、网盘单页 100 条；
   - 总量封顶 1000 条，超出提示「结果很多，建议加关键词或缩小范围」；
   - 「全部」模式下先出各来源首页，**不做自动无限翻页**，避免把每个群都翻到底；需要更多用更精确关键词或切到单群/网盘范围。
3. 结果弹窗沿用 `dialog_search_results.xml`，但：
   - 标题：`搜索 · 群组` / `搜索 · 我的网盘` / `搜索 · 全部`
   - 副标题实时显示进度：`已搜 2/5 个群 · 已找到 37 项`
   - 每条结果的 meta 增加来源前缀：`群「XX」` / `我的网盘`
   - 结果按「来源 → 名称」排序，来源间加分组标题（可选二期）
4. 点击结果：
   - 群条目：若 `entry.gid != gid`，先 `setActiveGroup(entry.gid)` 再 `locateSearchHit(...)`；
   - 网盘条目：目录走 `openSourceDirectory`，文件走 `openEntry`；
   - 定位失败保留弹窗并提示（沿用现有逻辑）。

### 2.3 数据与聚合设计
新增（`MainActivity` 内）：

```kotlin
private enum class SearchScope(val label: String) { DISK("我的网盘"), GROUP("群组"), ALL("全部") }
private var searchScope = SearchScope.DISK    // 默认我的网盘；读取 app_settings.search_scope

private data class SearchTarget(val scope: SearchScope, val sourceId: String, val name: String)

/** 按范围组装目标：GROUP = 全部已关联群组；DISK = 网盘；ALL = 两者。 */
private fun searchTargets(scope: SearchScope): List<SearchTarget> = buildList {
    if (scope != SearchScope.DISK) {
        shareSources().forEach { add(SearchTarget(SearchScope.GROUP, it.id, it.name)) }
    }
    if (scope != SearchScope.GROUP) {
        add(SearchTarget(SearchScope.DISK, DISK_SOURCE_ID, "我的网盘"))
    }
}
```

搜索任务采用**串行队列**（不能并发，因为 `load()` 的 `RequestLane.SEARCH` 只有一个 `searchRequestId`，并发会互相取消）：

```kotlin
private fun runGlobalSearch(keyword: String, targets: List<SearchTarget>) {
    val hits = mutableListOf<PanSearchHit>()
    val seen = mutableSetOf<String>()
    var index = 0
    fun next() {
        if (index >= targets.size) { renderDone(hits); return }
        val target = targets[index++]
        updateProgress(index - 1, targets.size, hits.size)
        searchOne(target, keyword,
            onResult = { page ->
                page.forEach { if (seen.add(dedupKey(it))) hits.add(it) }
                next()
            },
            onFailure = { next() })   // 单个来源失败不中断整体
    }
    next()
}
```

去重键：
- 群条目：`"G:${entry.gid}:${entry.fileId}"`
- 网盘条目：`"D:${entry.fileId}"`（同一文件不同目录出现时按 fileId 去重）

上限：单群沿用 800 条上限；全量结果封顶 1000 条，超出提示「结果过多，请加关键词」。

频控：每个来源之间 `web.postDelayed(200)` 再发下一个，避免短时间打多个 `basembox/group/search`。

| `MainActivity.kt` 新增 `SearchSession` | 封装结果弹窗、adapter、进度、取消（`searchRequestId++` 与 `searchDialog = null` 复用现有约定） |
| `MainActivity.kt` `searchFiles` / `searchDiskFiles` | 不改内部逻辑，抽出可复用的单来源函数 `searchGroupOnce` / `searchDiskOnce` 供聚合器调用；原方法保留供单范围入口 |

### 2.5 边界与异常
- 未登录/连接变化：沿用 `hasVerifiedAccount()` 与 `verifiedAccount == account` 双重校验；中途变化则终止并提示重搜。
- 某群已从 `shareSources()` 移除：跳过并计入「失败来源」。
- `errno == 2156`（无结果）按空页处理，继续下一个来源。
- 用户关闭弹窗：立即 `searchRequestId++`，队列 `next()` 内检测 `dialog.isShowing` 后停止。
- 搜索「我的网盘」仍需 `bdstoken`：复用 `ensureBdstoken`，失败则仅跳过该来源并标注。

### 2.6 验收用例
1. 三个群 + 网盘各存同一文件，全局搜索关键词：结果出现 3+ 条，去重符合预期（网盘 1 条、群按文件各 1 条）。
2. 关闭弹窗后，后台不再发新请求（日志仅到当前来源）。
3. 一个群接口报错（模拟 500/超时），其余来源结果仍展示，副标题提示「2 个来源失败」。
4. 点击其它群的结果，自动切群并定位到所在目录层级。
5. 结果 > 1000 条时提示上限，不卡死。

### 2.7 风险
- 多群搜索触发百度频控：串行 + 200ms 间隔 + 来源数上限（建议最多 8 个群）。
- `RequestLane.SEARCH` 与「定位目录」复用同一 lane：定位期间禁止再开新搜索（用 `searchDialog` 是否 showing 判定）。

## 3. V02-2 批量操作

### 3.1 范围（本版）
- 批量**收藏** / **取消收藏**
- 全选 / 反选 / 取消选择
- 批量下载与「加入播放列表」明确留 v0.4

### 3.2 交互设计
1. 入口：章节列表右上角增加「选择」按钮（`sectionRow` 内、`sortButton` 左侧），点击进入多选模式。
   - 说明：**不改用长按进入**，因为现有「音频长按 = 强制网页音频兜底」是用户可感知能力，避免回归。
2. 多选模式：
   - 顶栏 `sectionTitle` 变为「已选 N 项」，`sortButton` 隐藏；
   - 每行 `item_course` 显示勾选圈（`ic_check` 复用）；
   - 点击行 = 切换选中，不再打开文件；
   - 底部出现操作条（可复用 `filterBar` 位置或新增 `batchBar`）：`全选` / `收藏` / `取消收藏` / `完成`。
3. 退出多选：点「完成」或返回键，清空选择。
4. 收藏状态：已收藏的条目在勾选圈旁显示星标；批量收藏后 toast「已收藏 N 项」。

### 3.3 状态模型（`MainActivity`）
```kotlin
private var selectionMode = false
private val selectedKeys = LinkedHashSet<String>()   // entryKey(entry)
private var selectionScreen: Screen? = null
```
- 进入时记录 `selectionScreen = screen`；离开屏幕/刷新/切换筛选时强制退出并清空。
- `selectedKeys` 以 `entryKey(entry)`（`origin:sourceId:gid:messageId:fileId`）为准，跨分页稳定。

| 文件 | 改动 |

### 3.5 关键实现骨架
```kotlin
private fun enterSelection() {
    selectionMode = true
    selectionScreen = screen
    selectedKeys.clear()
    renderBatchBar()
    redrawFilteredRows?.invoke()
}
private fun exitSelection() {
    selectionMode = false
    selectionScreen = null
    selectedKeys.clear()
    renderBatchBar()
    redrawFilteredRows?.invoke()
}
private fun toggleSelection(entry: PanEntry) {
    val key = entryKey(entry)
    if (!selectedKeys.add(key)) selectedKeys.remove(key)
    renderBatchBar()
    redrawFilteredRows?.invoke()
}
private fun batchFavorite(add: Boolean) {
    val entries = visibleEntries().filter { entryKey(it) in selectedKeys }
    if (entries.isEmpty()) return
    if (add) favorites.addAll(entries) else favorites.removeAll(entries)
    updateFavoritesBadge()
    toast(if (add) "已收藏 ${entries.size} 项" else "已取消收藏 ${entries.size} 项")
    exitSelection()
}
```
> `visibleEntries()` = 当前 `redrawFilteredRows` 作用域内经过筛选/排序后的列表；实现时把 `renderRows()` 里的 `ordered` 缓存为成员 `lastRenderedEntries`。

### 3.6 边界
- 目录条目：v0.2 允许选择并收藏目录（现有 `Favorites` 支持目录），批量收藏语义一致。
- 筛选变化导致已选条目不可见：仍保留选中（按 key），「全选」只作用于当前可见项。
- 平板双栏：多选状态只在列表侧生效，不影响播放器。
- 无障碍：勾选圈 `contentDescription = "已选/未选：${entry.name}"`。

### 3.7 验收
1. 进入多选、全选 20 条、批量收藏 → 收藏页出现 20 条，角标 +20。
2. 批量取消收藏后恢复原状。
3. 切换筛选/退出屏幕后选择清空，不串页。
4. 原有「音频长按走网页音频」在非多选模式仍可用。
5. 深色/平板下勾选圈可见、可点。

## 4. V02-3 睡眠定时

### 4.1 交互
- 音频播放页**顶部栏右侧**（收藏左侧）增加「定时」图标按钮；视频**顶部栏**（收藏左侧）增加同款按钮（见 10.5 布局）。
- 菜单项：`关闭定时` / `15 分钟` / `30 分钟` / `45 分钟` / `60 分钟` / `本集结束后停止`。
- 按钮：未开启为常规图标色；开启后图标变 `accent` 强调色；`contentDescription` / 长按提示剩余时间（如「睡眠定时，剩余 28:13」），不占额外布局宽度。
- 「本集结束后停止」与定时可叠加：先到者生效。

### 4.2 架构设计（跨进程一致）
新增进程内单例（`SleepTimer.kt`）：
```kotlin
internal object SleepTimer {
    @Volatile var deadlineElapsedMs: Long = 0L          // 0 = 未开启
    @Volatile var stopAfterCurrent: Boolean = false
    fun arm(minutes: Int) { deadlineElapsedMs = SystemClock.elapsedRealtime() + minutes * 60_000L }
    fun disarm() { deadlineElapsedMs = 0L }
    fun armStopAfterCurrent() { stopAfterCurrent = true }
    fun consumeStopAfterCurrent(): Boolean = stopAfterCurrent.also { stopAfterCurrent = false }
    fun remainingMs(): Long = (deadlineElapsedMs - SystemClock.elapsedRealtime()).coerceAtLeast(0L)
    fun fired(): Boolean = deadlineElapsedMs > 0 && remainingMs() == 0L
}
```

**音频（后台也要生效）**：定时逻辑必须放在 `AudioPlaybackService`，不能只放 Activity。
- `AudioPlaybackService` 增加 `SessionCommand SLEEP_TIMER`（args: `minutes: Int`，0 表示取消）。
- Service 内 `handler` 调度：`arm` 后 `postDelayed` 到点 `player.pause()`，并 `SleepTimer.disarm()`。
- `onDestroy`/`clearFile` 时移除定时回调。
- Activity 仅负责发命令与显示剩余时间（读 `SleepTimer.remainingMs()`）。

**视频**：`VideoPlaybackPage` 内 `Handler` 定时 `player.pause()`；因视频与 Activity 同生命周期，无需服务。
- 视频「本集结束停止」：在 `onPlaybackStateChanged(STATE_ENDED)` 调 `canAutoAdvance()` 前检查 `SleepTimer.consumeStopAfterCurrent()`，为 true 则不回调 `onEnded`。

**音频「本集结束停止」**：`MainActivity.advanceAfterEnd(...)` 的 `tryNext()` 首行判断 `SleepTimer.consumeStopAfterCurrent()`，为 true 时直接 return（不播下一节）。

### 4.3 具体改动清单

| 文件 | 改动 |
|---|---|
| 新增 `SleepTimer.kt` | 进程内单例（如上） |
| `AudioPlaybackService.kt` | 新 `SessionCommand SLEEP_TIMER`；`onConnect` 注册；`onCustomCommand` 处理；`handler` 定时暂停；清理回调 |
| `MainActivity.showPlayback()` | **顶部栏右侧**增加定时图标 + 菜单；`update()` 里刷新剩余时间；发送 `SLEEP_TIMER` 命令 |
| `MainActivity.advanceAfterEnd()` | `tryNext()` 开头消费 `stopAfterCurrent` |
| `VideoPlaybackPage.kt` | **`topBar`** 增加定时图标 + 菜单；`onPlaybackStateChanged` 检查 `stopAfterCurrent`；`Handler` 定时暂停 |
| `res/drawable/ic_timer.xml` | 新增时钟图标（可选） |

### 4.4 边界
- 进程被杀：定时自然失效（可接受；不做唤醒锁）。
- 音频切歌：定时不重置；「本集结束停止」只对当前集生效一次。
- 视频退出全屏/画中画：定时继续。
- 通知栏不额外显示定时，避免改动媒体通知布局；如需可在 `MediaMetadata` 标题临时拼「（28:13 后停）」——列为可选。

### 4.5 验收
1. 音频设 1 分钟（测试用可临时暴露秒级），后台锁屏也在到点暂停。
2. 视频到点暂停，画面停在当前帧。
3. 「本集结束后停止」：音频播完当前集不自动下一节；视频播完不回 `onEnded` 连播。
4. 菜单再次选择「关闭定时」立即取消。
5. 退出播放器再进入，定时状态归零（不跨会话续存）。

## 5. V02-4 未听 / 未完成筛选

### 5.1 交互
在现有筛选条下增加第二行进度筛选（`progressFilters`）：
- `全部`（默认）
- `未听`（无播放记录）
- `进行中`（有记录且未完成）
- `已完成`
仅在列表中存在音频/视频时显示；目录/文档不参与进度判断（切到进度筛选时目录行隐藏，避免「筛了还是有目录」的困惑）。

### 5.2 数据设计
新增枚举：
```kotlin
private enum class ProgressFilter(val label: String) { ALL("全部"), UNPLAYED("未听"), IN_PROGRESS("进行中"), COMPLETED("已完成") }
private var progressFilter = ProgressFilter.ALL
```

`AudioHistory` 增加一次性索引，避免每行 `find()` 线性扫描：
```kotlin
fun progressIndex(): Map<String, AudioHistoryItem> = runCatching {
    val prefix = AccountScope.prefix(account ?: AccountScope.current)
    preferences.all.keys.asSequence()
        .filter { it.startsWith(prefix) }
        .map { it.removePrefix(prefix) }
        .flatMap { bucket -> recentBucket(bucket).asSequence() }
        .associateBy { "${it.entry.origin}:${it.entry.sourceId}:${it.entry.gid}:${it.entry.messageId}:${it.entry.fileId}" }
}.getOrDefault(emptyMap())
```
> key 与 `MainActivity.entryKey` 完全一致；`AudioHistoryItem.entry` 已含 origin/gid/message/file。

`addFilteredCourseRows` 渲染前构建：
```kotlin
val progress = when (progressFilter) {
    ProgressFilter.ALL -> emptyMap()
    else -> audioHistory.progressIndex() + videoHistory.progressIndex()  // 后者覆盖前者同名 key 时以视频为准
}
fun progressOf(e: PanEntry): ProgressFilter = when {
    PanApi.kindOf(e) !in setOf(MediaKind.AUDIO, MediaKind.VIDEO) -> ProgressFilter.ALL
    progress[eKey]?.completed == true -> ProgressFilter.COMPLETED
    progress[eKey]?.seconds ?: 0 > 0 -> ProgressFilter.IN_PROGRESS
    else -> ProgressFilter.UNPLAYED
}
```
过滤时：`mediaFilter.includes(kind) && (!transferredOnly || matches) && (progressFilter == ALL || kind in 音视频 && progressOf == progressFilter)`。

计数显示在 chip：`未听 12` / `进行中 3` / `已完成 8`，每次渲染重算。

### 5.4 边界
- 历史数据缺失（新装/换号）：全部视为「未听」，符合预期。

## 6. V02-5 多账号快速切换

### 6.1 能力边界（必须先说清）
`CookieManager` 是应用级单例，WebView Cookie 全局共享，**无法让两个百度账号同时在同进程各持一份登录态**（除非启用多个 WebView 数据目录并重启进程，代价高、易崩）。因此 v0.2 的「多账号」= **账号档案 + 一键登出/重登 + 本地数据按 uk 隔离**：
- 本地收藏、历史、播放进度、目录缓存**已经**按 `AccountScope.key()` 分桶（`acct_<uk>__`），切换后天然不串。
- 切换账号需要重新走一次网页登录（不保存任何凭据）。

### 6.2 数据模型（扩展 `AccountScope`）
```kotlin
data class AccountProfile(val uk: String, val label: String, val lastUsedAt: Long)

fun register(context: Context, uk: String)          // 登录成功时写入/更新档案
fun profiles(context: Context): List<AccountProfile>
fun label(uk: String): String = "账号 …${uk.takeLast(4)}"   // 只显示尾 4 位，不存敏感信息
fun clearLocalData(context: Context, uk: String)     // 删除 acct_<uk>__ 前缀的所有键
```
存储：`account_scope` SharedPreferences 新增键 `accounts` = JSON 数组 `[{"uk","label","lastUsedAt"}]`，最多保留 10 个。

`clearLocalData` 需遍历 5 个命名空间 SharedPreferences：`audio_history`、`video_history`、`favorites`、`video_progress`、`course_cache`，删除 `AccountScope.prefix(uk)` 前缀键。

### 6.3 交互设计
- 设置页「数据源」卡片上方或账号卡右侧增加「账号」行：
  - 当前：`已登录 · 账号 …1234`
  - 点击进入「账号管理」弹窗：
    - 列出已登录过的账号（label + 最近使用时间）
    - 当前账号打勾
    - 操作：`切换`（对该账号重新登录）/ `清除本地数据` / `添加账号`
- 切换流程（确认弹窗）：
  1. `CookieManager.getInstance().removeAllCookies { }` + `flush()`
  2. `web.clearCache(true)` + `web.clearHistory()` + `web.loadUrl(PanApi.MOBILE_HOME)`（回登录页）
  3. `verifiedAccount = ""`、`invalidateAccount()`、`refresh()`
  4. 用户在网页/登录弹窗重新登录，`probeAccount` 成功后 `AccountScope.set(...)` → `AccountScope.register(...)`
- 登录成功即注册档案（`probeAccount` 内 `confirmed` 时调用 `AccountScope.register`）。

### 6.4 具体改动清单

| 文件 | 改动 |
|---|---|
| `AccountScope.kt` | 增加 `AccountProfile`、`register/profiles/label/clearLocalData`；`set` 不变 |
| `MainActivity.probeAccount()` | `confirmed` 后调用 `AccountScope.register(this, uk)` |
| `MainActivity.renderSettings()` | 增加「账号」行与当前 label |
| `view_settings_page.xml` | 增加 `setAccountSwitchRow`（标题「账号与切换」，副标题当前 label，右侧 chevron） |
| `MainActivity` 新增 `showAccountManager()` | 账号列表弹窗 + 切换/清理/添加动作 |
| `MainActivity` 新增 `switchAccount(profile)` | 清 Cookie/缓存/历史 + 回登录 |
| `MainActivity` 新增 `clearAccountData(profile)` | 二次确认后 `AccountScope.clearLocalData` + 若为当前账号则 `refresh()` |

### 6.5 边界
- 清除 Cookie 后百度可能要求短信验证：属百度侧行为，UI 需提示「切换需重新登录，按网页提示完成验证」。
- `removeAllCookies` 是异步回调；必须在回调里再 `loadUrl`，否则可能残留。
- 当前正在播放：切换前 `stopBackgroundAudio()`、关闭视频页，避免旧账号媒体串播。
- 账号档案不含任何 Cookie/token/密码，仅 uk 尾号与时间。
- 档案上限 10，超出淘汰最久未用；提供手动删除。

### 6.6 验收
1. A 账号登录 → 收藏 3 条；切换 B 账号登录 → 收藏页为空；切回 A → 收藏恢复 3 条。
2. 设置页显示当前账号尾号；账号管理列出 A、B。
3. 「清除本地数据」只清该账号，另一个账号数据不受影响。
4. 切换过程中旧播放停止，无串号音频。
5. 重新登录同一账号不产生重复档案。

| 风险 | 影响 | 缓解 |

## 12. 变更记录（评审后）

- **V02-5 多账号快速切换：已移除，不在 v0.2 交付范围。**
  - 原因：WebView `CookieManager` 为应用级单实例、全局共享，同一时刻只能持有单份 `pan.baidu.com` 登录态；关键 `BDUSS` 等为 HttpOnly Cookie，无法通过公开 API 导出/回灌。因此「切换账号」必须重新登录，无法做到「免重登的快速切换」，功能价值不成立。
  - 真正的多账号并行需为每个账号使用独立 WebView 数据目录并多进程隔离（`setDataDirectorySuffix` + 独立进程），成本与稳定性风险超出 v0.2，留待后续评估。
  - 落地处理：删除设置页「账号与切换」入口、账号管理弹窗与切换/清理逻辑、`AccountScope` 的档案模型（`AccountProfile/register/profiles/label/clearLocalData`）。本地数据仍按 `AccountScope.key()` 单账号分桶，不受影响。
- v0.2 实际交付改为 **V02-1 全局搜索 / V02-2 批量操作 / V02-3 睡眠定时 / V02-4 未听筛选** 四项。
