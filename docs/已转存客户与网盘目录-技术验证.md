## 0. 审核结论（先看这里）

上一版报告里「自己的网盘音频不能走 HLS」的结论**不成立**，本次已修正；其余审核结论保持（含 2 个排除项、3 个降级/未知项）：

| # | 项目 | 审核结论 |
|---|---|---|
| 1 | 自己的网盘音频走 HLS | **成立（R）**。`/api/streaming` + `type=M3U8_MP3_128` + 公共参数（`web/channel/bdstoken`）返回 m3u8；mp3 与 m4a 均可。首次请求可能返回 400 / 31341（转码未就绪），等待 1–2 秒重试 1–2 次即可；实际 217 集 m4a 课程目录抽测 5 条，最终全部返回 m3u8。`M3U8_AUTO_480` 对音频仍返回 31304，不要用错档 |
| 2 | `/api/filemetas` 返回的 dlink 可播放 | **不成立（R）**。网页参数是 `fsids`（不是 `target`）；即使返回 dlink，直接请求也会得到 31362 `sign error`。不要把它当播放地址 |
| 3 | 视频必须带 `jsToken` / VIP 值 | **本次未观察到必要性（R，单账号 / 480p）**。`jsToken` 为空、`vip=0/1/2` 均返回 m3u8。保留可选参数，但不要把“必须”写死 |
| 4 | 「已存在」按 `md5+size` 匹配 | **仍属推断（I）**。目录条目有 md5 字段，但群/网盘两侧的完整匹配、重命名、部分转存未端到端验证 |
| 5 | 非 SVIP / 多账号 / 更高清晰度 | **未知（U）**。本次只验证了一个登录账号；480p 的 `vip` 参数实测 0/1/2 都可用，但不能外推到所有账号和清晰度 |
| 6 | `/api/list` 省略 `bdstoken` 是否可用 | **未知（U）**。本次请求都带 `bdstoken`；实现时按“必须带”处理即可 |

**补充发现（R）**：个人 PDF 和群 PDF 都有不走 `/api/download` 的入口。

- **个人 PDF**：`pfile/docview` 底层调用 `/rest/2.0/docview/dlink`，返回 `bdcm01.baidupcs.com/file/...` 的 PDF 地址；UA-only Range 206、完整 200，大小 5,251,738 B。
- **群 PDF**：`pfile/imdocview` 底层调用 `POST /mbox/fileinfo/preview`（body：`fuk / scene=1 / gid / fsid / ftype=pdf / password`），返回 `data.dlink`；UA-only Range 206、完整 200，大小 2,605,439 B。
- 个人 docview dlink 对群 PDF 不适用（21061/210120/-31362，群 docview 页面 404）；群 PDF 用 `fileinfo/preview`，不需要走 `/api/sharedownload`（可作兜底）。
- `/api/download` 只作个人 PDF 兜底；群 PDF 兜底是现有 `/api/sharedownload`。

**置信度**：接口链路（R）高；对现有代码的落点（S）中高；匹配/去重（I）中低；工作量是估算，不是承诺。

## 1. 需求理解与范围

本文把「已转存的客户」定义为：**已经把这批课程转存到自己百度网盘、但不走/不想走群文件库的用户**。目标是在现有架构上增加第二类内容源：

1. **我的网盘文件夹**：用户选择自己网盘里的转存目录，App 直接列目录、播放；
2. **目录「已存在」切换**：在群目录与网盘转存目录之间切换，或标记/筛选已转存的文件；
3. **收藏 / 最近播放**：两类来源的条目都能收藏、续播、出现在首页。

不做的事（本期）：

- 不做全盘扫描 / 全盘搜索；
- 不做自动转存、不做分享链接体系；
- 不做服务端、不做账号体系；
- 不缓存媒体文件、不缓存 dlink / m3u8。

## 4. 验证结果

### 4.1 我的网盘目录：`GET /api/list`

**请求参数（R）**：

```text
/api/list
  ?clienttype=0&app_id=250528&web=1&channel=chunlei
  &bdstoken=<从 gettemplatevariable 获取>
  &dir=<目录路径>
  &order=name|time&desc=0|1
  &showempty=0&page=<页码>&num=<每页数>
```

**观察结果（R）**：

- 根目录 `/` 返回 `errno=0`，29 项；
- 一个 97 项目录，用 `num=50` 分页：第 1 页 50、第 2 页 47、第 3 页 0，页间 `fs_id` 无重叠；
- 一个 218 项实际课程目录（`.m4a` + 1 张 png），用 `num=100` 分页：100 / 100 / 18，页间无重叠；`md5` 全部存在；
- 响应没有 `has_more`，顶层键为 `errno / guid_info / list / request_id / guid`；
- `order=time&desc=1` 返回的 `server_mtime` 前 5 项递减；
- 列表项可用字段：`fs_id`、`path`、`server_filename`、`isdir`、`size`、`md5`、`server_mtime`、`category` 等。

**实现含义**：

- 分页用 `page` / `num`，**按“返回数量 < num”判断结束**，不要等 `has_more`；
- `md5` 可用于后续“已存在”匹配，但要对空值兜底；
- `bdstoken` 沿用现有 `gettemplatevariable` 获取方式（`fields=["uk","bdstoken"]`）。

**未知（U）**：

- 省略 `bdstoken` 是否可用未验证；
- 更大目录（>218 项）的翻页未压测；218 项已验证 100/100/18。

### 4.2 自己的网盘视频：`GET /api/streaming`

**请求参数（R）**：

```text
/api/streaming
  ?path=<文件路径，URL 编码>
  &app_id=250528&clienttype=0
  &type=M3U8_AUTO_480
  &isplayer=1&check_blue=1&adToken=&src_id=1
```

请求必须同源，并带 `pan.baidu.com` 登录 Cookie、`User-Agent`、`Referer: https://pan.baidu.com/disk/main`。

**观察结果（R）**：

- 200，`application/x-mpegURL`；
- 媒体列表（media playlist）约 119 KB，`#EXTM3U` + `#EXT-X-ENDLIST`，约 105 个分片；
- 首个分片在 `*.baidupcs.com`，**只带 `User-Agent: pan.baidu.com` 即可 206**（不需要 Cookie）；
- `jsToken` 为空也返回 m3u8；
- `vip=0 / 1 / 2` 均返回 m3u8（本次账号、480p）；
- 可选预检 `&nom3u8=1` 返回 JSON：`errno / adTime / adToken / ltime`；本次 `adToken` 为空，480p 不依赖它。

**实现含义**：

- 现有 `VideoStreamResolver`（带 Cookie、UA、Referer、X-Requested-With）可以直接用来拉这条 m3u8；
- `VideoPlaybackPage` 的 `HlsMediaSource` 链路不用改；
- 不需要做“原始 mp4 渐进播放”分支；
- `jsToken` / `vip` 作为可选参数保留，若未来接口要求，可从播放页内联脚本或账号档位补上。
- 音频也走这个接口，但 `type=M3U8_MP3_128`，见 4.3。

**未知（U）**：

- 非 SVIP / 多账号 / 720p、1080p 的行为；
- m3u8 无 Cookie 是否一定失败（本次带 Cookie 验证；分片已确认 UA-only）；
- 未来前端是否把 `jsToken` 变成强制参数。

### 4.3 自己的网盘音频：`GET /api/streaming`（HLS，推荐）

**请求参数（R）**：

```text
/api/streaming
  ?path=<文件路径，URL 编码>
  &app_id=250528&clienttype=0&web=1&channel=chunlei
  &bdstoken=<从 gettemplatevariable 获取>
  &type=M3U8_MP3_128
  &isplayer=1&check_blue=1&adToken=&src_id=1
```

**观察结果（R）**：

- 200，`application/x-mpegURL`；媒体列表（media playlist），`#EXTM3U` + `#EXT-X-ENDLIST`；
- mp3 与 m4a 均可用；实际 217 集 m4a 课程目录抽测 5 条，最终全部返回 m3u8，单条 75–131 个分片；
- 分片在 `bdnest.pcs.baidu.com/nest/ts/...`，**只带 `User-Agent: pan.baidu.com` 即可 206**；
- 首次请求可能返回 400 / **31341**（转码未就绪）；等待约 1–2 秒重试 1–2 次即可，抽测中 2 条首次 31341、重试后成功；
- 同一文件一旦成功过，后续请求通常直接 200；
- `jsToken` / `vip` 本次未观察到必要性；公共参数（`web/channel/bdstoken`）建议全带；
- 音频用 `M3U8_AUTO_480` 仍返回 31304，不要用错档。

**实现含义**：

- 音频复用现有 `AudioPlaybackService` 的 HLS 分支（`playlist != null`），不需要 `/api/download`；
- 新增 `PanApi.diskAudioPlaylist(path)`，与视频用同一个 `/api/streaming`，只换 `type`；
- 31341 重试 2–3 次（间隔 1–2 秒）；仍失败再走 `/api/download` 兜底；
- m3u8 可放 `MediaAddressCache` 缓存（6 小时）；分片地址 8 小时有效，失败重取；
- 这样正常听音频不再调用 `/api/download`，可显著降低验证码风险；但不能承诺无限频率绝不触发风控。

**未知（U）**：

- 31341 的转码预热时间是否固定；抽测 1.5–4 秒内成功，未做长尾统计；
- 非 SVIP / 多账号 / 更大体积的 m4a 是否都可用 `M3U8_MP3_128`；
- 转码音质/流量与原始文件差异（`M3U8_MP3_128` 是转码档，体积可能更大）。

### 4.3.1 个人 PDF：`GET /rest/2.0/docview/dlink`（推荐）

`pfile/docview` 只是网页阅读器；它底层实际调用这个接口拿到 PDF 地址，再用 PDF.js 分段读取。App 可以跳过 HTML 页面，直接调 JSON 接口。

**请求参数（R）**：

```text
/rest/2.0/docview/dlink
  ?clienttype=0&app_id=250528&web=1&channel=chunlei
  &scene=3
  &fuk=<当前账号 uk，gettemplatevariable 的 result.uk>
  &path=<PDF 路径>
  &fsid=<PDF fs_id>
  &file_type=pdf
```

**观察结果（R）**：

- `errno=0`；响应键：`dlink / dlink_type / file_type / need_passwd / real_size / src_size / info / request_id`；
- `dlink` 是 `bdcm01.baidupcs.com/file/...` 的 PDF 地址；
- 该 dlink **UA-only 即可**：`Range: bytes=0-1023` → 206 `application/pdf`；不带 Range → 200，完整大小 5,251,738 B，与文件一致；
- 不需要 `bdstoken`、`logid`、`dp-logid`（本次省略仍成功）；
- `fuk` 用当前账号 uk 即可；`scene=3`、`file_type=pdf`；
- 不需要 `/api/download`、不需要 `sign2`、不需要 302 解析；
- 群 PDF 不适用这条：实测 `/rest/2.0/docview/dlink` 对群 PDF 返回 21061/210120/-31362，群 docview 页面自身也 404。

**实现含义**：

- 自己的网盘 PDF：`load()` 调 `/rest/2.0/docview/dlink`，取 `dlink` 直接交给 `PdfFileFetcher`；下载器核心不用改；
- 检查 `errno`、`need_passwd`、`real_size`；密码 PDF 需要单独提示；
- dlink 不要缓存，约 8 小时过期；
- 个人 docview 失败时再走 `/api/download` 兜底；群 PDF 走 `fileinfo/preview`，失败再走 `/api/sharedownload`（实测 dlink UA-only 206/200 PDF）。

**未知（U）**：

- 非 PDF 文档（docx 等）的 docview dlink 是否同样可用；
- 需要密码的 PDF、超大 PDF 的预览/下载行为；
- docview 接口是否对所有账号/文件类型一致。

#### 群 PDF：`POST /mbox/fileinfo/preview`（`pfile/imdocview` 底层）

**请求（R）**：

```text
POST /mbox/fileinfo/preview
  ?clienttype=0&app_id=250528&web=1&channel=chunlei
Content-Type: application/x-www-form-urlencoded

fuk=<上传者 uk>&scene=1&gid=<群 gid>&fsid=<文件 fsid>&ftype=pdf&password=
```

**响应（R）**：

- `errno=0`；`data` 键：`dlink / layout_engine / office2pdf_link / page_num / page_info / pic_url`；
- `data.dlink` 是 `bdcm01.baidupcs.com/file/...` 的 PDF 地址；
- 该 dlink **UA-only 即可**：Range 206 `application/pdf`、完整 200，大小 2,605,439 B 与文件一致；
- `pfile/imdocview` 页面自身也用 PDF.js 读这个 dlink；App 可以跳过页面直接调接口；
- 不需要 `/api/sharedownload`、不需要 `/api/download`；
- `fuk` 用群文件的上传者 uk（`listshare` 的 `uk` 或 `recentv2` 的 `fuk`），不是当前账号 uk。

**实现含义**：

- 群 PDF：`POST /mbox/fileinfo/preview` 取 `data.dlink`，直接交给 `PdfFileFetcher`；
- 检查 `errno` 和 `page_num`；有密码时补 `password` 或提示；
- `pic_url` / `page_info` 可用于页图预览，但原生 PDF 阅读器不需要；
- 失败时回退现有 `/api/sharedownload`（实测 errno=0，dlink UA-only 206/200 PDF）。

**未知（U）**：

- 群内非 PDF 文档、加密 PDF、超大 PDF 的行为；
- `fuk` 与群权限变化时的失效处理。

### 4.3.2 兜底：`GET /api/download`（个人 PDF docview 失败）

**签名链路（R）**：

1. `GET /api/gettemplatevariable?fields=["sign1","sign2","sign3","timestamp","is_vip"]`
   - 注意：网页里出现的 `gettemplateletiable`（拼写错误）实测 404；正确接口是 `gettemplatevariable`。
2. `sign2` 是服务端下发的 **JS 函数源码**；
3. 在 WebView 里执行：
   ```js
   const fn = new Function('return ' + sign2)();
   const sign = binarySafeBase64(fn(sign3, sign1));
   ```
4. 请求：
   ```text
   GET /api/download
     ?sign=<上一步>
     &timestamp=<template.timestamp>
     &fidlist=[<fs_id>]
     &vip=<template.is_vip>
     &type=dlink
     &clienttype=0&app_id=250528&web=1&channel=chunlei&bdstoken=<token>
   ```
5. 响应 `dlink[0].dlink`。

**媒体链（R）**：

- 对上一步的 dlink 先发一次 **带 Cookie + UA** 的请求：返回 `302`，`Location` 是 CDN 地址；
- 对 `Location` 直接发 **UA-only** 请求：`206`；
- 实测 PDF `application/pdf`；音频 `audio/mpeg`（仅作兜底时用）。

**实现含义**：

- 个人 PDF docview 失败时走这条；群 PDF 优先 `fileinfo/preview`，失败再走 `/api/sharedownload`；音频仅在 31341 持续失败时兜底；
- 不需要改 `PdfFileFetcher` 的下载核心；新增一个“解析 302”的小函数：带 Cookie 请求 dlink，不跟随重定向，取 `Location`，再把 CDN URL 交给现有组件；
- 不要把 `sign2` 的算法硬编码；它随时可能变；
- 不要缓存 dlink，8 小时过期，失败重取；只有 docview 不可用时才走这里，批量/缓存 CDN 可减少 `/api/download` 调用。

**未知（U）**：

- 非 SVIP / 多账号的 `is_vip` 与 `/api/download` 行为；
- `sign2` 未来是否依赖额外上下文；
- `/api/download` 的验证码触发阈值（用户已遇到；docview/HLS/fileinfo/preview 路径不经过它，只有个人/群 PDF 兜底使用）。

### 4.4 `/api/filemetas` 的坑（R）

- 网页版参数是 **`fsids`**，不是 `target`：
  - `target=[fsid]` → `info[0].errno=-9` / `31021`；
  - `fsids=[fsid]` → `errno=0`，返回 dlink。
- 但这个 dlink 直接请求会得到 **31362 `sign error`**（WebView iframe 与宿主 curl 均复现）。
- 结论：**不要把 `/api/filemetas` 的 dlink 当播放地址**；视频/音频优先 `/api/streaming`，个人 PDF 优先 docview dlink，群 PDF 优先 `fileinfo/preview`；兜底才用 `/api/download` / `/api/sharedownload`。

---

### 4.5 群文件库链路（回归基线，S）

- 群视频仍走 `/mbox/msg/streaming`（`type=2`，HLS），现有 `VideoStreamResolver` + `VideoPlaybackPage` 不变；
- 群音频仍优先 `M3U8_MP3_128`，失败回退 dlink；
- 本次新增的是**第二条链路**，不是替换群链路；
- 任何来源抽象都不能改变群条目的 `gid / msg_id / fs_id` 语义，否则收藏和播放进度会错位。

---

### 4.6 收藏与最近播放（S）

- `Favorites` 已能保存目录和文件（`path`、`directory` 都在），收藏 tab 已有；
- `AudioHistory` 已按 gid 分桶、跨群合并，首页“继续播放”和“播放记录”已存在；
- 现在缺的只是**来源身份**：`origin` / `sourceId`，以及备份字段。

**需要改的点（S）**：

- `entryKey`、`favoriteTag`、`sameEntry`、`mediaCacheKey`、`VideoPlaybackPage.progressKey` 都要带来源；
- 历史记录的 JSON 增加 `origin` / `sourceId`；旧记录缺省按 GROUP；
- 收藏屏和历史屏显示来源名（群名 / “我的网盘”）；
- 备份 `SCHEMA 1 → 2`，旧备份仍可恢复。

---

### 4.7 「已存在」匹配（I，未端到端验证）

**建议方案**：

- 文件：群条目与网盘条目用 `md5 + size` 匹配；
- 目录：按相对路径 / 名称匹配；
- UI：先做「群文件 / 我的网盘」源切换；第二阶段再在目录里标记/筛选「已转存」。

**风险（I/U）**：

- 用户可能只转存部分、改名、移动目录；
- `md5` 可能为空或两侧不一致；
- 同一文件在群和网盘各有一份时，最近播放会出现重复；
- 因此不要把「已存在」作为 MVP 的硬依赖；先做源切换更稳。

| `/api/gettemplatevariable` | GET | `fields=["uk","bdstoken"]` | Cookie | 取当前账号 / bdstoken | `errno=0` |

| `/api/download` | GET | `sign / timestamp / fidlist / vip / type=dlink` + 公共参数 | Cookie | 个人 PDF 兜底 dlink | `errno=0`，302 → CDN |
| `/api/filemetas` | GET | `fsids`（不是 `target`） | Cookie | 元数据 | dlink 不可直接播（31362） |

**公共参数**：`clienttype=0`、`app_id=250528`、`web=1`、`channel=chunlei`；部分接口还需要 `bdstoken`。

**错误码（本次观察）**：

| 错误码 | 含义 / 场景 | 处理 |
|---|---|---|
| `errno=-6` | 未登录 / Cookie 失效 | 重新登录，刷新 |
| `31304` | 该类型不可用此转码档 | 换正确档位（音频用 `M3U8_MP3_128`） |
| `31341` | 音频 HLS 首次请求转码未就绪（自己的网盘） | 等 1–2 秒重试 2–3 次；仍失败再走 `/api/download` |
| `31362` | sign error（filemetas dlink 等） | 不要用该 dlink；换正确链路 |
| `302` | dlink 跳 CDN | 带 Cookie 取 `Location`，再用 UA-only 播/下 |
| `403` | 地址过期 / 防盗链 | 重新取址；不要缓存 |

## 7. 数据模型 / 来源抽象建议

```kotlin
enum class EntryOrigin { GROUP, DISK }

data class ContentSource(
    val id: String,          // 群：gid；网盘：稳定源 ID（可用 path hash / uuid）
    val kind: EntryOrigin,
    val name: String,
    val path: String? = null // 仅网盘源：用户选定的根目录
)

data class PanEntry(
    val gid: String,         // 群条目必填；网盘条目留空
    val messageId: String,   // 群条目必填；网盘条目留空
    val owner: String,       // 群条目必填；网盘条目留空
    val fileId: String,      // 群：fs_id；网盘：fs_id
    val name: String,
    val path: String,        // 网盘：完整路径；群：现有 path
    val size: String,
    val directory: Boolean,
    val origin: EntryOrigin = EntryOrigin.GROUP,
    val sourceId: String = gid,
)
```

**身份规则**：

- 群：`(GROUP, gid, messageId, fileId)`；
- 网盘：`(DISK, sourceId, fileId)`，`path` 只作为显示/定位快照，不作为唯一身份（重命名不丢）；
- 旧收藏/历史/备份没有 `origin` 时默认 `GROUP`。

**网盘源选择**：

- 设置页 / 来源选择器增加「添加我的网盘文件夹」；
- 浏览网盘目录到目标转存根，保存 `path`；
- 不做全盘扫描；首页“最近”对网盘源用 `/api/list?order=time&desc=1` 只列选定根目录的直接子项，或在 MVP 直接进入目录页。

## 9. 风险、边界与未验证项

| 类型 | 内容 | 处置 |
|---|---|---|
| 私有接口 | `/api/list`、`/api/streaming`、`/api/download`、`sign2` 都可能随前端发版变化 | 接口层集中封装；启动自检；失败提示；不要把参数写死到 UI |
| 签名 | `sign2` 是动态 JS，不能硬编码 | 每次播放/下载前取模板并执行；失败重试一次 |
| 过期 | dlink / m3u8 / 分片约 8 小时；部分视频链接可能只有 1 小时 | 播前实时取；403/31360 重新取；不缓存 |
| 账号 | 本次只验证一个账号；非 SVIP / 多账号未复测 | 多账号回归；`vip` 从 `is_vip` 读取，不写死 |
| 视频 | 480p 已验证；更高清晰度未验证 | MVP 固定 480p；更高档位后续按账号档位做 |
| 音频 | 首次 `/api/streaming` 可能 31341（转码未就绪）；HLS 是转码档，音质/流量与原始文件可能不同 | 31341 等 1–2 秒重试 2–3 次；仍失败走 `/api/download` 兜底；m3u8 缓存 6h |
| PDF | 个人 docview 需 `need_passwd=0`；群 `fileinfo/preview` 需 `fuk/scene/ftype`；加密/非 PDF 未验证 | 个人失败走 `/api/download`；群失败走 `/api/sharedownload` |
| 验证码 | `/api/download` 高频可能触发验证码；HLS 路径不经过它 | 音频优先 HLS；PDF 批量取 dlink / 缓存 CDN，减少调用；不承诺无限频率 |
| 匹配 | `md5+size` 匹配是推断；部分转存/改名会失败 | 先做源切换；匹配放 Phase 2；失败可降级为“未匹配” |
| 搜索 | 自己的网盘搜索未验证 | MVP 不做，或只搜本地缓存 |
| 首页 | 网盘源没有 `recentv2` 等价的跨目录聚合 | 首页只列选定根目录的直接子项，或默认进目录 |
| 合规 | 私有接口 + 分发给客户会放大账号风险和维护成本 | 技术可行不等于建议大规模分发；沿用现有评估口径 |

## 10. 验收 / 负面测试

**正向**：

- 添加一个自己的网盘文件夹源，能列出根目录、连续下钻 3 级、分页加载；
- 网盘视频 480p：ExoPlayer HLS 播放 10 分钟、seek、切网、后台音频；
- 网盘音频：`/api/streaming` HLS 播放 10 分钟、续播、后台；冷文件首次 31341 时重试成功；持续 31341 才走 `/api/download` 兜底；
- 个人网盘 PDF：docview dlink 完整下载（大小/PDF 头正确）并打开；docview 失败时兜底 `/api/download`；
- 群 PDF：`POST /mbox/fileinfo/preview` 取 `data.dlink`，完整下载并打开；失败时兜底 `/api/sharedownload`；
- 收藏网盘文件 / 目录；收藏屏可打开对应位置；
- 最近播放跨群 / 网盘混排，来源名正确；同一文件两份时行为可解释；
- 备份/恢复：旧 SCHEMA 1 可恢复，新 SCHEMA 2 保存 sources/kind/path。

**负面**：

- 未登录 / Cookie 过期：明确提示，不崩溃；
- `bdstoken` 失效：重新获取或提示刷新；
- `/api/list` 返回 `errno != 0`：保留已有缓存并提示；
- `/api/download` sign 失败 / 302 无 Location / 403：提示重试，不缓存坏地址；
- docview / fileinfo/preview 返回 `need_passwd=1` / `errno != 0`：提示密码/错误，不静默失败；
- 音频首次 31341：等 1–2 秒重试 2–3 次；仍失败才兜底，不无限重试；
- 正常音频播放期间不应出现 `/api/download` 调用（可用日志确认，避免验证码）；
- 目录被删 / 文件被移动：收藏标失效，可移除；
- 大目录分页边界：返回数 < num 时停止，不无限请求；
- 多账号切换：来源、收藏、历史不串数据；
- 群链路回归：群视频/音频/PDF/收藏/历史不退化。

## 11. 安全与复现说明

1. 只在**已登录的 debug App / 同源页面**里验证；不要在 release 包或生产环境里留探针。
2. 不要把 `Cookie`、`BDUSS`、`STOKEN`、`jsToken`、`sign`、完整 `dlink` 输出到日志、聊天或仓库。
3. `dlink` / m3u8 只放内存/临时文件；验证结束删除。
4. 不要用裸 HTTP 重放私有接口；所有请求保持同源、带 Cookie。
5. 大目录不要全盘递归；只对用户选定的根/当前目录取一页或分页。
6. 若要复现，用调试版 App + WebView 调试协议，按以下顺序：
   - `gettemplatevariable` 取 `uk/bdstoken`；
   - `/api/list` 列目录；
   - `/api/streaming` 取网盘视频 m3u8（`M3U8_AUTO_480`）或音频 m3u8（`M3U8_MP3_128`，31341 重试）；
   - `/rest/2.0/docview/dlink` 取个人 PDF dlink（`scene=3&fuk=<uk>&path=<path>&fsid=<fsid>&file_type=pdf`）；
   - `POST /mbox/fileinfo/preview` 取群 PDF dlink（`fuk=<上传者 uk>&scene=1&gid=<gid>&fsid=<fsid>&ftype=pdf&password=`）；
   - docview/preview 不可用时：个人 PDF 走 sign + `/api/download`，群 PDF 走 `/api/sharedownload`；
   - 302 用 Cookie，CDN/docview/preview dlink 用 UA-only；
   - 只记录状态码 / content-type / 数量，不记录真实值。

## 12. 最终建议

1. **按 Phase 1 实施**：来源抽象 + 我的网盘文件夹 + 网盘视频/音频 HLS + 个人 PDF docview + 群 PDF `fileinfo/preview` + 收藏/历史来源标识。
2. **不要做**“原始 mp4 渐进播放”分支：网盘视频有 HLS，直接复用现有链路。
3. **音频优先 HLS**：`/api/streaming?type=M3U8_MP3_128`，31341 等 1–2 秒重试 2–3 次；`/api/download` 只作持续失败兜底，避免高频验证码。
4. **PDF 分两类**：个人网盘用 `/rest/2.0/docview/dlink`；群 PDF 用 `POST /mbox/fileinfo/preview`；两者 dlink 都 UA-only 直接下载；`/api/download` / `/api/sharedownload` 只作兜底。
5. **不要把 `/api/filemetas` 的 dlink 当播放地址**。
6. **「已存在」匹配放 Phase 2**：先做源切换，避免一开始就陷入目录映射、改名、部分转存的坑。
7. **上线前补**：多账号、非 SVIP、720p/1080p、弱网、链接过期、备份迁移、音频冷启动重试的回归。
