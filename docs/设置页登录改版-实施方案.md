# 设置页登录改版 · 实施方案

> 状态：**已实现并通过真机验证**（v0.1.23 debug，2026-11-10）
> 原型：`docs/prototype_settings_login.html`
> 涉及文件：`MainActivity.kt`、`res/layout/view_settings_page.xml`、`AccountScope.kt`、`QuarkPersonalDrive.kt`
> 原则：**只改编排层与设置页布局，不动数据链路**（`shareSources()` / `showSourcePicker` / `manageQuarkSources` 现有预勾选能力全部复用）

---

## 1. 背景与目标

当前设置页把"登录"和"选来源"拆成了三条互不相干的入口：

- 百度网盘登录行
- 夸克网盘登录行
- 「通讯录文件库」→ 管理群组/联系人来源

用户诉求是把它收敛成一条引导流：

> **添加登录 → 选择网盘类型 → 弹出登录窗口 → 登录成功 → 选择来源（百度选群组、非百度选关注的目录）**
> 已登录过的网盘**不再出现在"添加登录"里**；**没有可用的网盘就不显示"添加登录"**；登录后可以**退出登录**（等价于"暂时不用"，**数据保留**）。

### 目标

| # | 目标 |
|---|---|
| G1 | 设置页由「两条登录行 + 一个来源入口」改为「已关联网盘卡片 + ＋添加登录」 |
| G2 | 同一网盘**只允许一个账号会话**，登录过的网盘从"添加登录"列表永久移除 |
| G3 | 无任何可添加网盘时，隐藏"＋添加登录" |
| G4 | 支持"退出登录"：仅终止会话，**保留来源与播放数据**，可随时重新登录 |
| G5 | 进入来源选择时**自动预勾选历史来源**（现成能力，直接复用） |
| G6 | 百度来源**群组 + 联系人双入口并存**，不可择一（共享文件库两处都有） |

## 3. 核心设计：单网盘三态模型

每个网盘类型（`BAIDU` / `QUARK`）维护一个状态：

| 状态 | 语义 | 设置页表现 | 是否出现在「添加登录」 |
|---|---|---|---|
| `never` | 从未设置过 | 不出现在已关联区 | ✅ 唯一出口 |
| `active` | 已登录，会话有效 | 已关联卡片，标「在用」，提供「退出登录」 | ❌ |
| `dormant` | 曾登录，已退出，**数据保留** | 已关联卡片，标「已退出」，提供「登录」 | ❌ |

### 3.1 状态迁移

```
                 登录成功
      never ──────────────────▶ active
        ▲                        │  │
        │                        │  └── 退出登录 ──▶ dormant
        │                        │                     │
        │                        └──── 点卡片 ──▶ 来源管理（跳过登录）
        │                                              │
        └────────────── 不回流 ────────────────────────┘
                              重新登录 ──▶ active
```

**核心不变式**：`never → 一旦离开，永不回流`。即"登录过的网盘不再出现在添加列表"（G2）。`dormant` 只能通过自身卡片的「登录」回 `active`，不经过"添加登录"。

### 3.2 状态判定来源

| 状态 | 判定 |
|---|---|
| 百度 `active` | `hasVerifiedAccount()` == true |
| 百度 `dormant` | `AccountScope.current` 非空 且 `hasVerifiedAccount()` == false |
| 百度 `never` | `AccountScope.current` 为空 **且** `acct_*__share_sources` 中无 BAIDU 来源 |
| 夸克 `active` | `QuarkPersonalDrive.hasLoginCookie(...)` == true |
| 夸克 `dormant` | 存在 QUARK 来源，但 `hasLoginCookie` == false |
| 夸克 `never` | 无 QUARK 来源，且无夸克登录 Cookie |

> 注：夸克无显式"账号 uk"，`dormant` 只能靠"是否还留着 QUARK 来源"推断。若用户退出时来源为空，夸克会退回 `never`（可接受，见 8.2 风险）。

### 3.3 "没有可用的网盘就不显示添加登录"

```
hasNever = (百度状态 == never) || (夸克状态 == never)
addBtn.visibility = hasNever ? VISIBLE : GONE
```

当两个网盘都已是 `active/dormant` → 整条"＋添加登录"隐藏。

## 4. 交互流程

### 4.1 主流程：添加登录

```
设置页
  └─ 点「＋ 添加登录」
       └─ 底部弹窗「添加登录」（只列 never 的网盘）
            ├─ 选「百度网盘」→ LoginDialog(WebView) ─成功→ 选来源（群组 / 联系人，预勾选历史）→ 保存 → active
            └─ 选「夸克网盘」→ QuarkDriveActivity ─成功→ 选来源（关注的目录，预勾选历史）→ 保存 → active
```

要点：
- 弹窗里**绝不出现**已 `active/dormant` 的网盘。
- 仅剩一个 `never` 时，弹窗只显示该项（是否省略弹窗直达，见 8.3）。
- 登录被取消/失败 → 状态保持 `never`，不产生脏数据。

### 4.2 已关联网盘卡片

| 卡片状态 | 点击行体 | 右侧操作 |
|---|---|---|
| `active` | 直接进来源管理（**跳过登录**） | 「退出登录」 |
| `dormant` | 起对应登录流程，成功后进来源管理 | 「登录」 |

### 4.3 退出登录

```
点「退出登录」→ 二次确认 → 仅终止会话
  百度：清 WebView 登录态（导航到登出页 / 清 pan.baidu.com Cookie）
  夸克：精确清除 pan.quark.cn / *.quark.cn 的会话 Cookie（__pus/__puus）
  ↓
invalidateAccount()（清内存与缓存）
  ↓
状态 → dormant；share_sources、播放记录、续播点 全部保留
  ↓
提示「已退出，数据已保留，可随时重新登录」
```

⚠️ **禁止 `CookieManager.removeAllCookies()`**：百度与夸克共用同一个 CookieManager，全局清会误杀另一个网盘的会话。必须按域名逐个 `setCookie(url, "name=; Max-Age=0")` 精确失效。

### 4.4 重新登录（dormant → active）

- 点卡片「登录」→ 起对应登录 → 成功后 `renderLinked()` 刷新为 `active` → 再进来源管理确认（历史来源仍预勾选）。
- 若换成了**另一个百度账号**：`AccountScope.uk` 变化 → 旧来源属于旧命名空间，**新账号下自然为空**，不硬选、不报错（这是期望行为，符合"按账号隔离"）。

## 5. 数据保留与隔离

| 数据 | 位置 | 退出登录时 | 说明 |
|---|---|---|---|
| 来源列表 | `acct_<uk>__share_sources` | **保留** | 重新登录同账号即恢复 |
| 当前选中来源 | `acct_<uk>__group_id` | 保留 | — |
| 播放记录/续播点/收藏/课程缓存 | `acct_<uk>__*` | 保留 | `AccountScope.NAMESPACED` 已隔离 |
| 百度会话 | WebView Cookie | 清除 | 仅 baidu.com 域 |
| 夸克会话 | `CookieManager` quark 域 | 清除 | 仅 *.quark.cn 域 |
| `AccountScope.viewer_uk` | prefs | **保留** | 这是"数据仍归属谁"的锚点，不能清 |

> 若清 `viewer_uk`，会退回 `guest` 命名空间，导致"数据看似丢了"。**退出登录只清会话，不动 `viewer_uk`。**

## 8. 决策记录（已拍板 · 2026-11-10）

| # | 决策 | 结论 |
|---|---|---|
| **D1** | "只能一种网盘登录"的含义 | **每种网盘单账号，百度 + 夸克可共存** |
| **D2** | 夸克 `dormant` 如何识别 | **新增 `quark_ever_logged` 标记**，退出后不因来源为空退回 `never` |
| **D3** | 只剩一个 `never` 时 | **仍弹"选择网盘类型"**，流程恒定不特判 |
| **D4** | 百度联系人 / 群组来源 | **两个都保留，不可择一（关键）** |

### 8.1 D1 落地

`hasNever` 显隐只判断"是否存在 `never`"，**不限制同时 active 的网盘数量**：

```kotlin
val hasNever = baiduState == NEVER || quarkState == NEVER
addBtn.isVisible = hasNever
```

即：百度 active 时"添加登录"仍可出现（里面只有夸克）；两者都 active/dormant 时才整条隐藏。

### 8.2 D2 落地

退出夸克时写（不清除）：

```kotlin
getSharedPreferences("account_scope", MODE_PRIVATE).edit()
    .putBoolean("quark_ever_logged", true).apply()
```

`quarkState()` 判定改为：

```kotlin
QUARK active  : QuarkPersonalDrive.hasLoginCookie(...) == true
QUARK dormant : !hasLoginCookie && (quarkEverLogged || 存在 QUARK 来源)
QUARK never   : !hasLoginCookie && !quarkEverLogged && 无 QUARK 来源
```

### 8.3 D3 落地

`openAddLoginSheet()` 不判断候选数量，恒弹 sheet；候选恒为 `never` 集合。

### 8.4 D4 落地（关键点）

**原因**：百度网盘的**共享文件库**有的挂在「群组」下、有的挂在「联系人」下。只做群组会直接漏掉一批来源，因此两个入口都必须保留。

**实现约束**：

1. `manageBaiduSources()` **保留**「群组 / 联系人」二级选择（现有代码本就有，禁止删减）。
2. 两组选择结果合并写入同一份 `share_sources`，**互不覆盖**：
   `showSourcePicker()` 中 `candidateIds` 只覆盖当前 tab 的候选，`retained = shareSources().filterNot { it.id in candidateIds }` 天然保留另一类来源。
3. 联系人来源 id 带 `CONTACT_SOURCE_PREFIX`，由 `isContactSource(id)` 判定归属 tab（现有实现，直接复用）。
4. 设置页来源计数用 `shareSources().size`，**群组 + 联系人合计**，不分类计数。
5. 原型：百度来源页为「群组 / 联系人」双 tab，两侧各自预勾选历史。实现首版可复用现有二级选择 sheet（最小改动），后续再统一为单页双 tab。

> 遗漏检查：任何 `contacts = false` 硬编码、或把 `manageBaiduSources()` 改写为只走 `discoverSources(contacts = false)` 的改动，都属于**破坏 D4**，禁止。

## 9. 风险与边界

| 风险 | 说明 | 对策 |
|---|---|---|
| R1 误清另一个网盘 Cookie | 共用 `CookieManager` | 严格按域名失效（C7） |
| R2 退出后 `viewer_uk` 被清 → 数据"消失" | 会落到 guest 命名空间 | 退出**只清会话不清 uk** |
| R3 换百度账号后旧来源失效 | `AccountScope` 按 uk 隔离，gid 属旧账号 | 期望行为：新账号下来源为空，让用户重选 |
| R4 百度会话被动过期（非主动退出） | `hasVerifiedAccount()` 变 false，但 uk 还在 → 会显示 `dormant` | 这正是想要的效果：卡片提示"已退出·数据保留"，点登录恢复 |
| R5 夸克 Cookie 判定漏域 | `hasLoginCookie` 取的是 `HOME` 域 Cookie | 退出与判定使用同一组 URL，保持一致 |
| R6 添加流程中用户取消登录 | 状态仍为 `never` | 不写任何数据，无副作用 |

### 12.3 登录串联

- 百度：`showLoginDialog(SourceProvider.BAIDU)` → `LoginDialog` 成功后置 `pendingAddProvider` → `showApp(recheck=true)` → `verifyAndRefresh()` 的 `confirmed` 分支消费标记 → `manageBaiduSources()`。
- 夸克：`startLoginFor(QUARK)` 先置标记 → 拉起 `QuarkDriveActivity` → 回调中 `quarkLoggedIn()` 成立则 `manageQuarkSources()`；未登录则清标记。
- 退出：`clearCookies()` 同时失效 host-only 与 `.domain` 两种 Cookie，**不调用 `removeAllCookies`**，不动 `AccountScope.viewer_uk`。
