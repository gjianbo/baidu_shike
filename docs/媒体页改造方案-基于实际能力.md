## 三、设计原则（只取夸克三条，不照抄形态）

| 原则 | 夸克做法 | 我们的落地方式 |
|---|---|---|
| **P1 一屏一个主体** | 视频满屏画面 / 音频唱片 / 图片原图，其余收进抽屉 | 去掉音频常驻课程列表、来源/状态两行；视频不做 Tab；图片不加信息面板 |
| **P2 控制尽量一行、集中在底部** | 视频单行控制条；音频底部一坨 | 视频控制层三行 → 一行；音频控制全部沉底，中间留白 |
| **P3 顶栏轻、动作收进更多** | 透明、两行标题、`···` | 顶栏改透明 + 两行标题；低频动作收进 `···` 弹层，**唯独高频的转音频常驻顶栏耳机**；竖屏已有列表，不重复放选集 |

**不采用夸克的地方（必须写清）**

1. **不做「文件详情页」结构。** 夸克竖屏有底部主导航与系统返回，播放器只是详情页顶部一个区块；我们的视频/音频是 `Dialog`/覆盖式 View（`VideoPlaybackPage.kt` 用 `dialog.setContentView`，`MainActivityPlayback.kt:946` 用 `accessibilityPaneTitle`），没有页面栈与底部导航。改成详情页要动返回栈与后台音频，风险远大于收益。
2. **不做 Tab / AI / 文稿。** 没有对应能力，做出来也是空壳。
3. **不做多档清晰度与投屏。** 服务端单档、无 Cast 依赖。
4. **顶栏不完全隐藏（竖屏）。** Dialog 没有系统返回入口，顶栏必须保留返回；横屏才全隐。

## 四、三页具体方案

### 4.1 视频播放页

```
A 顶栏 48dp（透明 + 顶部 scrim）
    ←  文件名（15sp）
        来源目录 · 3/31（11sp 灰）   [🎧 转音频] [···]
B 内容：16:9 画面，全出血，零常驻 chrome
    └ 单击唤出（3 秒收起）：C' 单行控制条【叠在画面内底部，不占布局高度】
        ⏸  00:21 ─────●───── 44:06   1.0x   ⛶
      （收藏 / 定时 / 文件信息 → 顶栏 ··· 弹层；竖屏列表已常驻，不再放选集）
D 课程列表：位置恒定（top = 画面下沿），显隐不改变任何占位 → 无空白
```

- **改动落点**：`VideoPlaybackPage.kt:212-350`（动作 cell / 传输组）、`:554-560`（topBar）、`app/src/main/res/layout/view_video_controls.xml`（把进度行与动作槽合并成一行）。
- **叠加的关键**：`arrangePlayer()` 里把 `videoFrame.bottomMargin` 从 `controlsHeight` 改为 **0**，画面渲染区铺满 stage，PlayerView 的 bottom bar 自然叠在画面底部（夸克真机的做法）。叠加后不再需要 `:629` 的 `reserve = if (controllerVisible) ...` 动态让位逻辑，可一并简化；课程列表的 `listTop` 固定为画面下沿。
- **可读性**：画面底部保留渐变 scrim（`v-frame` 已有），保证亮画面下白字时间与轨道可读。
- **动作集合**：控制条只留 `播放/暂停 · 进度 · 倍速 · 全屏`；`···` 弹层只放 `收藏 / 定时 / 文件信息` 三项。
- **竖屏不再放「选集」入口**：画面下方课程列表已常驻，再放一个入口是重复（现代码 `courseButton.root.visibility` 也只在横屏才显示，方向一致）。**横屏没有列表，选集保留在单行控制条右端**（与夸克横屏的「选集」文字按钮同位）。
- **转音频常驻**：用户高频使用，不藏菜单——**竖屏顶栏 `···` 左侧固定一个耳机按钮**（`R.drawable.ic_headset`），点击切音频态并高亮，再点恢复画面；`···` 菜单里不再重复这一项。仍只在竖屏视频页出现，**横屏与音频页都不设**（转音频的语义是收起画面，与横屏看满屏互斥）。
- 实现上复用现有 `listening / setListening() / audioStage`（`VideoPlaybackPage.kt:238-250`、`:163-211`），只是把触发点从 D 槽/菜单搬回顶栏，逻辑不用重写。
- **选集列表**：复用 `loadRecentThumbnail()` 加缩略图；可显示「已观看 X%」（本地进度），**不显示超清/时长**。

### 4.2 音频播放页

```
A 顶栏 48dp（透明）
    ⌄                                    ···
B 内容（flex，居中）
    圆形封面 220dp（现有 ic_audio_wave + 圆形底，不承诺唱针动画）
    标题一行 17sp
    ── 大片留白 ──
C 5 格动作栏（进度条上方）
    倍速 · 定时 · −30 · +30 · 收藏 · 更多
D 进度行 40dp      00:28 ───●─── 03:13
E 传输组 72dp       ‹    ▶(64dp 大圆)    ›    ☰列表
```

- **列表改抽屉**：`☰列表` 打开 `BottomSheetDialog`（Material3 已可用），主列表不再常驻；现有 `courseCell` 的 AlertDialog 逻辑（`MainActivityPlayback.kt:882-908`）换成 BottomSheet 即可。
- **改动落点**：`MainActivityPlayback.kt:799-1083`（**注意：拆分后音频页在这里，不是 MainActivity.kt**）。
- **±30 秒**：现有长按上一/下一保留，另外把 `−30 / +30` 显式放进动作栏（夸克是 ±15，我们沿用 30 秒，与通知栏/线控一致，不另造数值）。
- **封面**：可复用 `PanEntry.previewUrl` + `loadRecentThumbnail` 做真实封面；取不到时回落圆形波形图。
- **暂不做**：转文字、真实唱片动画。下载能力其实已具备（`DownloadManager` + `shareSet`），但需要按音频文件补一次取址，先排到 S3 之后，不进首版。

### 4.3 图片浏览页

```
A 顶栏 48dp（透明）
    ←   文件名（15sp，MIDDLE 截断）
        2026-11-08 11:48 · 3 / 9（11sp 灰）   ···
B 图片全出血
    └ 底部胶囊：原图 941KB · 1920×1080
C 动作栏 66dp，图标 24 + 标签 10.5sp
    上一张 · 下一张 · 收藏 · 分享 · 保存 · 更多
```

- **改动落点**：`ImageViewerActivity.kt:171-231`（`topBar()` / `bottomBar()` / `textButton()`）。
- **数据来源**：`localFile.length()` → 大小；`ImageDecoder.ImageInfo.size` → 宽高（`:410-411`）；日期/索引从 intent 与 `index/count` 拿（`:111`）。
- **分享**：`ACTION_SEND` + `FileProvider.getUriForFile`（`:365` 现成）。
- **保存**：MediaStore.Images 插入，`minSdk 29` 不需要写权限。
- **收藏**：复用 `Favorites`（`Favorites.kt:12`）。
- **不做**：修图、AI、拍摄地点。

## 七、验收清单

- [ ] 竖屏顶栏有常驻耳机按钮，点一下切音频态并高亮、再点恢复；横屏无此按钮
- [ ] 竖屏 `···` 菜单不含「选集」（下方列表已常驻）；横屏控制条右端有「选集」入口
- [ ] 视频控制层只占一行且**叠在 16:9 画面内底部**，画面下沿与课程列表上沿重合
- [ ] 控制层显隐不改变任何布局高度，收起后画面零 chrome、无空白黑条
- [ ] 顶栏透明，亮画面下标题仍可读（scrim）
- [ ] 音频页无课程列表常驻，点「列表」能上滑出抽屉，关闭后布局不变
- [ ] 图片页两行标题 + 尺寸胶囊，分享/保存能用真机验证
- [ ] 三页都不出现 AI / 文稿 / 字幕 / 投屏 / 清晰度等空壳入口
- [ ] 拆分后的文件落点正确（`MainActivityPlayback.kt` 而非 `MainActivity.kt`）
- [ ] Android 侧跑 `:app:assembleDebug`，真机逐页截图（三页各一张显示态 + 一张收起态）

---

**结论**：夸克能学的是「一屏一个主体 + 控制尽量一行 + 顶栏轻」，不是它的功能清单。
我们真正缺的是**减法**（去掉常驻列表、冗余文字、三行控制层），不是补 AI。
所有 P0 项都是纯 View 改动，零新接口、零新依赖；之前判断为「做不到」的抽屉与分享，实际能力都在。
