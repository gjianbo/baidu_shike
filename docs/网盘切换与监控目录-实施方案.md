# 网盘切换与监控目录 · 就地分派实施方案

> 版本：v0.3　日期：2026-11-10　分支：`main_multi_disk`（基于 `95b71e9`）
> 状态：**待评审，未落代码**。本文是首版落地口径；`多网盘融合-重构实施方案.md`（v0.2 五层分层）延后为 Phase 2。
> 证据标注：**S** = 源码观察；**R** = 已实测；**U** = 未验证；**D** = 设计决策；**P** = 用户已拍板。
> 核心思路：**不动 UI 结构，只换数据源**。把「群组」从百度专有实体降级为「一组来源」，UI 语义保留、底层按 provider 分派。

## 0. 结论与已定决策

**可行，且比五层重构轻得多。** 底部 4 个 tab、列表渲染、筛选条、收藏/进度、播放器 UI 全部不用改；改的是「当前来源 → 走哪条数据链路」的分派。**但有一个必须先系统梳理的面**：`hasVerifiedAccount()` 在 `MainActivity` 里被调了 **49 处**（S），它是纯百度账号判据，不统一处理会让夸克来源处处被拦（详见 §5）。


- 只有两个网盘项，没有群组 / 联系人 / 监控目录 —— 那些属于首页与群组的「来源」概念。

> **布局约束（S）**：GROUPS 页已有 `btnBrowse` 一个 chip，titleRow 再加第二个 chip 会挤压（`appTitle` weight=1、`sourceName` maxWidth=116dp）。现在改成「复用同一下拉」，连第二个 chip 都不需要，布局零改动。首页的来源 chip 在 `sectionRow`，与 `titleRow` 完全分离，因此「首页顶部不动」与「群最新更新区块可选来源」两件事互不冲突。DISK 页沿用原有 `btnQuarkDrive` 位置，不新增控件。

### 1.3 `QuarkDriveActivity` 的新角色

降级为**设置页**，只保留：登录 WebView（含阿里云风控兜底）、`showCookieImport()` 导入 Cookie、监控目录选择。列表 / 播放 / 管理不再从这里进。好处：夸克登录链路不再暴露成主界面。

## 2. 三条数据流的分派

### 2.1 HOME：只换「群最新更新」的数据源

**首页 90% 不动**：大标题、顶栏、收藏、最近播放、播放进度、`renderHomeSections()` 全部原样。唯一变化是「群最新更新」区块的数据按**当前选中来源**的 provider 取：

| 项 | 百度来源（现状） | 夸克 / 其他来源（首版新增） |
|---|---|---|
| 入口 | `refresh()` :2164 → `startHomeCheck()` :2577 → `PanApi.recent(gid)` :2587 | 同一入口，`DriveSourceRouter` 按 `activeSourceId()` 的 provider 分派到「监控目录合并」 |
| 后台轮询 | `maybeCheckHomeInBackground()` :2606 | 同样按 provider 分派 |
| 结果应用 | `applyHomeRecent()` :2618 解析百度 recent 响应 | 新增 `applyMonitoredRecent()`，产出 `List<PanEntry>` 后走**同一个** `display()` :3014 |
| 缓存 key | `recent:$gid` (:2143) | `recent:<带 provider 前缀的来源 id>`，沿用 `courseCache.writeIfChanged`，多来源天然隔离 |
| 渲染 / 标题 | `display()` :3014、`sectionTitle`「群最新更新」 | **完全一样**，标题不改、筛选 chips 不改、行渲染不改 |
| 空更新 | :2240 显示「群内暂无更新」+ 跳 GROUPS 按钮 | **保持现状，不改**（用户已定首页不动）；如需兜底放到监控目录页，见 §8 #6 |

> 关键约束：`startHomeCheck()` :2587 现在**硬编码** `PanApi.recent(gid)`，`applyHomeRecent()` :2618 也只认百度响应结构。下拉里选到夸克监控目录后，这两处（加 :2606 后台轮询）必须按 provider 分派 —— 这是首页唯一必须改的代码，但**集中在 3 个函数内，不涉及任何控件**。
> 收藏 / 最近播放是全局数据（`Favorites` / `AudioHistory` 按 `AccountScope` 存），不参与 provider 分派，也不受下拉选择影响。

## 3. 来源模型：复用外壳，替换发现流程

### 3.1 可复用 / 必须替换（S）

| 组件 | 位置 | 处置 |
|---|---|---|
| `ShareSource(id, name, sessionUrl)` | :277 | **复用**，扩展 provider 维度（§3.2） |
| `share_sources` SharedPreferences + `shareSources()` / `saveShareSources()` | :1080 / :1238 | **复用**，多来源存储与当前来源 id |
| `chooseSource()` + `showChoiceSheet()` 多选 UI | :1092 / :1198 | **复用**外壳 |
| `renderSourcePicker()` | :3006 | **复用**，显示当前来源名 |
| **`discoverSources()`** | :1137-1196 | ❌ **不能复用**：里面 `PanApi.contacts()` / `PanApi.groups()` / `/api/gettemplatevariable` 的 bdstoken 全是百度专有 |
| **`showSourcePicker()` 里的 `isContactSource()` 过滤** | :1202 | ❌ 按百度「群组/联系人」二分，夸克要换成「监控目录」候选 |
| `manageSources()` 的百度登录门禁 | :1124 | 换成当前 provider 会话判据（§5） |

**结论**：「和百度复用、只是来源不一样」= 复用**来源列表 / 切换 / 多选保存 / 持久化**这一层；**发现候选来源的方式**按 provider 各自实现：百度从通讯录/群组列表发现，夸克从网盘目录树里勾选目录。

### 3.2 🔴 来源 id 的正则冲突（必须处理）

夸克 `fid` 是 **32 位十六进制**（`夸克网盘接口分析.md` §1.4），而现有多处把来源 id 当百度数字/联系人 id 校验：

| 位置 | 判据 | 对 fid 的结果 |
|---|---|---|
| `PanApi.isShareSourceId()` :15 | `Regex("(?:contact-)?[0-9]{1,24}")` | ❌ 不匹配 |
| `discoverSources()` :1165 | `id.matches(Regex("[0-9]{1,24}"))` | ❌ 不匹配 |
| `BackupStore.kt:197` | `isShareSourceId(groupId)` | ❌ 备份恢复会拒掉夸克来源 |
| `MainActivity` WebView 拦截 :341-349 | `group.matches(Regex("[0-9]{1,24}"))` | ❌ 群组路由失效（但夸克不走这条） |

**处置（D）**：来源 id 加 provider 前缀，`baidu:<gid>` / `baidu:contact-<uk>` / `quark:<fid>`；`ShareSource` 增加 `provider: SourceProvider` 字段（枚举定义见 §6，老数据无字段时按「纯数字或 contact-」推断为 BAIDU，保证向后兼容）。`isShareSourceId()` 扩展为「有前缀则校验前缀合法 + 本体格式；无前缀走老正则」。**备份/恢复必须同步改**，否则夸克来源在恢复时被静默丢弃。

## 4. 监控目录的「最新更新」怎么算

夸克**没有 `recent` 接口**（接口分析 §2 无对应端点）。首版方案：

1. 用户配置的每个监控目录 fid，各发一次 `GET /1/clouddrive/file/sort?pdir_fid=<fid>&_page=1&_size=20&pr=ucpro&fr=pc`。
2. 客户端按 `l_created_at` / `l_updated_at` 合并、按 `fid` 去重、倒序取 Top N（这两个字段在接口分析 §2.1 实测响应里）。
3. 映射到 `PanEntry`，写 `recent:<带前缀来源 id>` 缓存，复用 `courseCache.writeIfChanged` 做变更检测。
4. 结果两个去处：**首页「群最新更新」区块**（选中该来源时按 §2.1 走同一个 `display()`）与**监控目录页的「N 项更新」角标**。首页不做空更新兜底，也不改标题。

| 未验证项（U） | 说明 |
|---|---|
| `_sort` 按时间排序的取值 | 实测只用过 `file_type:asc,file_name:asc`；**不要依赖服务端时间排序**，客户端自己排 |
| `recent_file_list` / `last_view_list` | 接口分析 §2.1 实测响应里是空数组，语义未验证，不能用 |
| 目录递归深度 | 首版只取每个监控目录**第一层**；是否递归下钻待定 |
| 监控目录数量上限 | N 个目录 = N 次请求，建议上限 5 个并串行/并发控制 |

## 5. 会话门禁：本方案最大的改动面

`hasVerifiedAccount()`(:273) = `verifiedAccount.isNotEmpty() && verifiedAccount == AccountScope.current`，是**纯百度 uk** 判据；`ready` 是「WebView 在 pan.baidu.com」。全文件共 **49 处**调用（S）。若不处理，切到夸克后 `refresh()`(:2164)、`refreshDisk()`(:2334)、`updateNav()`(:858/:860/:864/:868)、`renderHomeSections()`(:4404/:4451) 会直接显示「登录百度网盘」。

**处置（D）**：保留 `hasVerifiedAccount()` 作为百度专有判据，新增统一入口：

```kotlin
// 显式传 provider，避免"当前该按哪页算"的隐式歧义
private fun hasActiveSession(p: SourceProvider = currentPageProvider()): Boolean =
    when (p) {
        SourceProvider.BAIDU -> ready && hasVerifiedAccount()
        SourceProvider.QUARK -> QuarkPersonalDrive.hasLoginCookie(
            CookieManager.getInstance().getCookie(QuarkPersonalDrive.HOME)
        )
    }

private fun currentPageProvider(): SourceProvider =
    if (screen == Screen.DISK) DriveSourceRouter.diskProvider()
    else DriveSourceRouter.providerOf(DriveSourceRouter.activeSourceId())
```

> **按「当前页面所属 provider」判（P）**：网盘页用 `diskProvider()`，首页与群组用 `activeSourceId()` 的前缀。两个状态彼此独立（§1.2 / §6），所以判据必须**按页面取**，不能用单一全局网盘值 —— 否则网盘页切到夸克后仍走百度判据，或首页选了夸克来源却被百度登录态拦住。
> **判据留在 Activity、不进 Router**：`ready` / `verifiedAccount` / `web` / `screen` 都是 `MainActivity` 私有状态，独立 object 取不到。Router 只提供 `activeSourceId()` / `diskProvider()` / `providerOf()`；`hasActiveSession()` 是 MainActivity 内的私有函数，作为 49 处调用点的统一替换目标。**Router 不定义 `sessionReady()`**（v0.1 草案里写过，已删）。
> **首页全局模块例外**：收藏 / 最近播放仍走 `hasVerifiedAccount()`（它们本就是百度账号维度的全局数据），不随来源切换，属于下表「保留百度专有」一类。

| 分类 | 代表位置 | 处置 |
|---|---|---|
| **第一批必须换**（浏览 / 导航 / 三页渲染） | :2164 `refresh`、:2334 `refreshDisk`、:2313 `refreshFavoritesPage`、:858/:860/:864/:868 `updateNav`、:793 `showScreen`、:2457 首页渲染、:2606 后台检查、:3489 `runDiskWrite`、:3609 `promptNewFolder` | 换 `hasActiveSession()`，约 **11~14 处**；首页收藏/最近播放相关的 :4404/:4451 保持百度判据 |

## 6. DriveSourceRouter：把分派点收在一处

为避免 `if (quark)` 散落，所有 provider 判断集中到一个对象：

```kotlin
internal enum class SourceProvider { BAIDU, QUARK }
internal enum class WriteOp { CREATE, RENAME, MOVE, DELETE }
internal typealias DriveCallback<T> = (Result<List<T>>) -> Unit

internal object DriveSourceRouter {
    fun activeSourceId(): String                        // 状态①：首页/群组的来源 id（带 provider 前缀），持久化
    fun setActiveSource(id: String)
    fun providerOf(sourceId: String): SourceProvider    // 从前缀解析，供会话判据与各处分派使用

    fun diskProvider(): SourceProvider                  // 状态②：网盘页当前网盘，独立持久化（默认沿用上次）
    fun setDiskProvider(p: SourceProvider)

    fun listRoot(cb: DriveCallback<PanEntry>)           // GROUPS 根目录（按 activeSourceId）
    fun listDiskRoot(cb: DriveCallback<PanEntry>)       // DISK 首页列表（按 diskProvider）
    fun listChildren(parent: PanEntry, cb: DriveCallback<PanEntry>)
    fun recent(cb: DriveCallback<PanEntry>)            // 首页「群最新更新」区块（按 activeSourceId）
    fun search(keyword: String, page: Int, cb: DriveCallback<PanEntry>)   // 按当前页面取状态①或②
    fun resolvePlayback(entry: PanEntry, cb: (Result<android.net.Uri>) -> Unit)
    fun download(entry: PanEntry, cb: (Result<android.net.Uri>) -> Unit)
    fun write(op: WriteOp, entry: PanEntry?, name: String = "",
              cb: (Result<Unit>) -> Unit)
}
```

> **两个状态，各有归属（P）**：`activeSourceId` 只服务首页「群最新更新」与群组页；`diskProvider` 只服务网盘页。互不同步 —— 首页选了夸克监控目录，网盘页仍停在百度也不矛盾；网盘页切到夸克，首页仍看原百度群组也不矛盾。这两个值分别持久化（`share_sources` 之外，`diskProvider` 建议存 `SharedPreferences` 单值）。`search()` 是唯一同时被两页调用的方法：网盘页搜索走 `diskProvider`，群组页搜索走 `activeSourceId`，由调用方显式传入，不在 Router 里猜。

> 草案里用到的 `SourceProvider` / `WriteOp` / `DriveCallback` 都在本段给出定义（v0.1 草稿曾写 `ProviderId` / `WriteOp` / `cb: ...` 三个未定义符号，已修）。**会话判据不在这里**（`ready` / `verifiedAccount` 是 Activity 私有状态），见 §5。

| 需要接入 Router 的分派点 | 位置 |
|---|---|
| **来源下拉**（首页 `homeGroupChip` / GROUPS `btnBrowse`） | :1092 `chooseSource`、:3006 `renderSourcePicker`、:1080 `shareSources`；统一列表、按网盘分组 |
| **网盘切换器**（DISK `btnQuarkDrive`） | `updateNav()` :847 可见性、:848 `startActivity`；改为 `setDiskProvider()` + 重载本页，面板只列两个网盘 |
| HOME 更新检查 / 结果应用 | :2577 `startHomeCheck`(:2587 硬编码 `PanApi.recent`)、:2606 `maybeCheckHomeInBackground`、:2618 `applyHomeRecent` |
| GROUPS 根目录 / 下钻 | :2738 `loadRoots`(:2742 硬编码 `PanApi.roots(gid)`)、:2961 `loadChildren` |
| DISK 列表 / 搜索 / 分页 | :2403 / :3246 / :4028 / :1575 / :1725 |
| DISK 写操作 | :3497 `submitWrite`、:3608/:3620/:3630 三个 prompt |
| 播放 / 下载取址 | :4800 `requestDiskFileLink`、:4931 `requestMediaLink`、:5024 `requestPdfLink` |
| 不做 | :2240 空更新分支、:2729 提示文案 —— 首页冻结，保持现状 |
