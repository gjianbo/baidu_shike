# 百度网盘 · 图片地址分析（缩略图 / 看图大图，不走下载接口）

> 版本：v1.0　生成日期：2026-11-10
> 适用：`pan.baidu.com` 网页版（新盘 `/disk/main`，登录态）
> 目标：**不经过 `dlink` 下载原文件**，直接拿到图片的展示地址，支撑「快速上一张/下一张」与「批量看图库」。
> 证据来源：真实登录态实测（R，2026-11-10，App 内隐藏 WebView 同源 `fetch` + 独立主机 `curl` 交叉验证）；标注 S 的为推断，未抓包证实。
> 关联：`docs/夸克网盘图片地址分析.md`（夸克对照）、`docs/媒体取址技术方案.md`（dlink / streaming 等原文件取址）。

## 0. 结论：图片不需要下载接口，列表就自带 4 档签名缩略图

| 用途 | 来源 | 地址形态 | 鉴权 | 实测 |
|---|---|---|---|---|
| 宫格小图 | 文件项 `thumbs.icon` | `https://thumbnail0.baidupcs.com/thumbnail/<THUMB_ID>?fid=…&size=c60_u60&…` | **免 Cookie**（URL 自带签名） | ✅ R |
| 列表缩略图 | `thumbs.url1` | 同上，`size=c140_u90` | 免 Cookie | ✅ R |
| 中图 | `thumbs.url2` | 同上，`size=c360_u270` | 免 Cookie | ✅ R |
| **看图大图（推荐）** | `thumbs.url3` + 改 `size` | 同上，`size=c1600_u1600` / `c2560_u2560` | 免 Cookie | ✅ R |
| 视频封面 | `thumbs.url*`（`ft=video`） | 同上 | 免 Cookie | ✅ R |
| 原图（真·原字节） | `dlink`（`/api/download`、`/api/sharedownload`） | `https://d.pcs.baidu.com/file/…` | 需换链（Cookie） | ✅ 既有方案 |

> **关键点**：`GET /api/list?...&web=1` 返回的每个文件项**自带 `thumbs` 对象**（icon / url1 / url2 / url3），是**已签名的 CDN 缩略图地址**；`size` 参数**不参与签名**，可以自由改成任意尺寸，CDN 会按原始分辨率封顶缩放。
> 因此「看图 + 上一张/下一张」完全可以在缩略图通道完成：**一次列表拿全部地址，翻页零请求**（仅按需拉 JPEG 字节），不碰 `dlink`、不排队、不等转码。这正是网页版切图快的原因（网页端实际请求未抓包，此句为 S；但机制等价可复现，见 §3 实测）。

## 1. 地址从哪来：`/api/list?web=1` 自带 `thumbs`

用户给的地址 `https://pan.baidu.com/disk/main#/index?category=all&path=%2F%E7%85%A7%E7%89%87%2F%E6%AC%A3%E8%93%89`
对应的数据接口就是目录列表：

```
GET https://pan.baidu.com/api/list
    ?clienttype=0&app_id=250528&web=1&channel=chunlei
    &bdstoken=<BDSTOKEN>
    &dir=/照片/欣蓉          # 就是 URL 里的 path（URL 解码后）
    &order=time&desc=1&num=100&page=1
Cookie: 登录态
X-Requested-With: XMLHttpRequest
Referer: https://pan.baidu.com/disk/main
```

响应（实测，字段已裁剪；`<…>` 为脱敏占位）：

```json
{
  "errno": 0,
  "list": [
    {
      "fs_id": <FS_ID>,
      "server_filename": "wx_camera_1625008209421.jpg",
      "path": "/照片/欣蓉/wx_camera_1625008209421.jpg",
      "isdir": 0,
      "size": 666512,
      "md5": "……",
      "category": 6,
      "thumbs": {
        "icon": "https://thumbnail0.baidupcs.com/thumbnail/<THUMB_ID>?fid=<UK>-250528-<FS_ID>&rt=pr&sign=<SIGN>&expires=8h&chkbd=0&chkv=0&dp-logid=<DP_LOGID>&dp-callid=0&time=1794290400&size=c60_u60&quality=100&vuk=<UK>&ft=image",
        "url1": "…&size=c140_u90&quality=100&vuk=<UK>&ft=image",
        "url2": "…&size=c360_u270&quality=100&vuk=<UK>&ft=image",
        "url3": "…&size=c850_u580&quality=100&vuk=<UK>&ft=image"
      }
    }
  ],
  "request_id": …
}
```

要点（实测 R）：

1. **不需要额外参数**：只要 `web=1`（项目现有 `PanApi.api()` 已固定带 `web=1`），图片/视频项就带 `thumbs`。**`web=0` 时 `thumbs` 完全消失**（对照实测）。
2. `thumbs` 有四个键：`icon`（c60_u60）、`url1`（c140_u90）、`url2`（c360_u270）、`url3`（c850_u580）。
   四者**除 `size=` 外完全相同**。
3. `ft=image` 为图片；`ft=video` 为视频首帧海报（见 §9）。
4. 目录项（`isdir=1`）没有 `thumbs`。
5. `/api/search`（搜索命中）返回的文件项同样带 `thumbs`（实测 R）。

## 2. 缩略图 URL 结构解剖

```
https://thumbnail0.baidupcs.com/thumbnail/<THUMB_ID>?fid=<UK>-250528-<FS_ID>&rt=pr&sign=<SIGN>&expires=8h&chkbd=0&chkv=0&dp-logid=<DP_LOGID>&dp-callid=0&time=<TS>&size=<SIZE>&quality=100&vuk=<UK>&ft=<image|video>
```

| 参数 | 含义 | 可否改 | 实测结论 |
|---|---|---|---|
| `<THUMB_ID>`（路径段，32 位十六进制） | 缩略图对象 id，按 `md5`+尺寸族生成 | ✗ | 改任意一位 → 判定为另一个资源/失败 |
| `fid` | `<UK>-250528-<FS_ID>`，即「用户 uk + 应用 id + 文件 fs_id」 | ✗ | 指向具体文件 |
| `rt` | 资源类型，`pr`（预览） | ✗ | 参与签名 |
| `sign` | `FDTAER-<固定串>-<32位base64签名>` | ✗ | **改一个字符即 403**（见 §4 对照实验） |
| `expires` | 有效期策略，`8h` | ✗ | 参与签名；实际有效期 ≈ 8 小时 |
| `time` | 签发时间戳（秒） | ✗ | 参与签名 |
| `vuk` | 签发账号 uk | ✗ | 参与签名 |
| **`size`** | 目标盒子，`c<宽>_u<高>` | **✓ 可任意改** | **不参与签名**，换尺寸仍 200（见 §3） |
| `quality` | JPEG 质量，`100` | ✓ 可改（不参与签名） | 未逐档测；保持 100 最稳 |
| `chkbd` / `chkv` / `dp-logid` / `dp-callid` | 风控/日志字段 | ✓ 无实质影响 | 保留原值最稳 |

- 尺寸语法：`c<W>_u<H>`；语义为「等比缩放到不超过 W×H 的盒子」。例：`c140_u90` 对 886×1920 的竖图输出 40×90（按短边约束）。
- **同一 `THUMB_ID` + `sign` 可跨尺寸复用**：只要改 `size`，不必重新调接口换签名。

## 3. size 自由替换实测（同一张图，只改 `size`）

同一 `thumbs.url3`（竖图，原图 886×1920 / 666,512 B），仅替换 `size` 参数：

| `size` | HTTP | Content-Type | 字节数 | 实际像素 |
|---|---|---|---|---|
| `c140_u90` | 200 | image/jpeg | 2,233 | 40×90 |
| `c850_u580`（原 url3） | 200 | image/jpeg | 26,275 | 268×580 |
| `c1600_u1600` | 200 | image/jpeg | 122,077 | **886×1920** |
| `c2560_u2560` | 200 | image/jpeg | 122,077 | 886×1920 |
| `c4096_u4096` | 200 | image/jpeg | 122,077 | 886×1920 |

视频封面（`ft=video`）同样成立：

| `size` | HTTP | 字节数 | 实际像素 |
|---|---|---|---|
| `c850_u580` | 200 | 85,780 | 850×480 |
| `c1600_u1600` | 200 | 101,628 | **960×544** |

**两条硬结论**：

1. **`size` 不在签名覆盖范围内**，任意替换都不影响 200。
2. **CDN 以原始分辨率为上限，不会放大**：`c1600` / `c2560` / `c4096` 三者字节完全一致，说明已顶到原图尺寸。
   → 实践上直接请求 `size=c2560_u2560` 即可拿到「能拿到的最大版本」（大多数手机照片原图就 ≤2560 长边，等于原图质量，只是 JPEG 重编码）。

## 4. 签名校验对照实验（证明 `sign` 有效、`size` 不在其中）

| 实验 | 结果 |
|---|---|
| 原样请求 | 200 image/jpeg |
| 仅替换 `size=c1600_u1600` | 200 image/jpeg（122,077 B） |
| **篡改 `sign` 中一个字符** | **403 text/plain** |
| 去掉 `Cookie`、不设 `User-Agent` | 200 image/jpeg（同字节） |
| 换一台机器 / 换出口 IP（独立主机 `curl`） | 200 image/jpeg（同字节） |

→ 结论：`sign` 绑定的是 `fid/rt/time/expires/vuk`（及资源本身），**不含 `size`、不含调用方身份/IP**。所以：

- 缩略图地址**可以跨设备、跨网络直接发**，不依赖登录态、不依赖 UA；
- 只要在有效期内，**改尺寸照样有效**。

## 5. 为什么它比 `dlink` 快（机制差异）

| 维度 | 缩略图通道（本文） | 下载通道（`dlink`） |
|---|---|---|
| 入口 | 一次 `/api/list?web=1` 就带回全部地址 | 每个文件都要先换链（`/api/download` 或 `/api/sharedownload`，需 `sign1/sign2/timestamp` 或 group 表单） |
| 鉴权 | URL 自带签名，**免 Cookie** | 换链需 Cookie；下链本身带签名 |
| 体积 | 2 KB ~ 120 KB（按 `size`） | 原文件全量（几 MB） |
| 是否转码/排队 | CDN 直出 JPEG，无任务 | 大文件可能受限速/额度影响 |
| 翻页体验 | 列表已含 N 张地址，**预取相邻即可瞬时切换** | 每张都要换链 + 拉全量，切换卡顿 |
| 代价 | 有损、**最高到原始分辨率**、8 小时过期 | 无损原字节、可长期保存 |

> 所以「快速上一张/下一张」的正确姿势：**列表时一次拿齐 `thumbs`，预览用 `size=c2560_u2560` 预取前后各一张**；只有用户主动「看原图 / 保存原图」时才回落 `dlink`。

## 6. 有效期与缓存策略

- `expires=8h` + `time=<签发时间>`：**约 8 小时**后 URL 失效（再请求会 403/过期页）。
- **`THUMB_ID` 与 `size` 稳定不变**，变的是 `sign/expires/time/dp-logid`。
  → 客户端磁盘缓存的 key 只取 `THUMB_ID + size + ft`，**忽略签名类参数**，这样列表刷新后仍命中缓存（这点已在设计里注明，代码不必改）。
- 失效处理：发现 403/非图片内容时，**重新拉一次 `/api/list` 换新签名**即可，不要复用旧 URL。

| 请求 | `thumbs` |
|---|---|

| `/api/list?web=0…` | ❌ 无 |

项目里 `PanApi.api()` 已固定拼 `web=1`，所以**现有 `diskList` / `diskSearch` 的响应里本来就带着 `thumbs`，只是当前代码没解析它**。

## 8. 目录与层级：`recursion=1` 只到一层（重要）

实测（R）：

| 请求 | 结果 |
|---|---|
| `/api/list?dir=/照片&recursion=1&num=100` | 70 项，**含 24 个目录**（= 与不带 `recursion` 完全一致） |
| `/api/list?dir=/照片/欣蓉&recursion=1&num=100` | 36 个文件、0 目录（该目录本身无子目录，所以看起来像递归） |

→ **`/api/list` 的 `recursion=1` 不生效**，只列一层。要跨子目录取图，两条路：

1. **`/api/search` 递归**：`GET /api/search?dir=/照片&recursion=1&key=.jpg&num=100&page=1`
   实测返回 500 条即封顶（服务端上限），`key=` 为空则 `errno:2`。适合「只按扩展名抓，能接受 500 上限」。
2. **BFS 自己走目录**（推荐做图片库）：逐目录 `/api/list`，把 `isdir=1` 入队，文件按扩展名/`ft=image` 收集；可自己设「目录数上限 / 图片数上限 / 进度提示」，不受 500 限制，也便于断点续扫。

`/api/categorylist`（新盘「图片」分类页可能的接口）实测 `category=1..7` **全部返回 0 条**，当前账号下不可用，不建议依赖。

## 9. 视频首帧海报

视频项的 `thumbs` 是**视频首帧**（`ft=video`），同样 4 档、同样可换 `size`。可直接当封面用在列表/图片库里，不需要另找视频截图接口。

## 10. 与夸克对照

| 维度 | 百度（本文） | 夸克（见 `docs/夸克网盘图片地址分析.md`） |
|---|---|---|
| 缩略图字段 | 文件项 `thumbs.icon/url1/url2/url3` | 文件项 `thumbnail` / `big_thumbnail` |
| 缩略图鉴权 | **免 Cookie**（URL 自带签名） | 需 Cookie（无 Cookie → 401） |
| 尺寸可调 | ✅ 改 `size` 即可，不参与签名 | 服务端固定尺寸（`thumbnail`/`quick` 二选一） |
| 看图大图 | ✅ `size=c2560_u2560`，封顶原图 | ✅ 独立的 `preview_url`（预签名 WebP，约 3h） |
| 有效期 | ≈ 8 小时 | `thumbnail` 长期；`preview_url` ≈ 3 小时 |

→ 百度这条链路比夸克更省事：**连 Cookie 都不用**，一个 `size` 参数就能当「看图大图」用。

## 11. 接口速查

| 目的 | 请求 | 关键参数 |
|---|---|---|
| 取 uk + bdstoken | `GET /api/gettemplatevariable` | `fields=["uk","bdstoken"]` |
| 目录列表 + 缩略图 | `GET /api/list` | `web=1&dir=<绝对路径>&order=time&desc=1&num=100&page=N&bdstoken=…` |
| 跨目录抓图 | `GET /api/search` | `web=1&dir=<根>&recursion=1&key=.jpg&num=100&page=N` |
| 下载会话签名 | `GET /api/gettemplatevariable` | `fields=["sign1","sign2","sign3","timestamp","is_vip"]` |
| 原图换链（我的盘） | `GET /api/download` | `fidlist=[<fs_id>]&type=dlink&sign&timestamp&vip&bdstoken` |
| 缩略图本体 | `GET https://thumbnail0.baidupcs.com/thumbnail/<THUMB_ID>` | `fid/rt/sign/expires/time/size/quality/vuk/ft` |
| 原图本体 | `GET <dlink>` | UA=`pan.baidu.com`，302 → CDN |

公共参数：`clienttype=0&app_id=250528&web=1`（列表类再加 `channel=chunlei`）、`X-Requested-With: XMLHttpRequest`、`Referer: https://pan.baidu.com/disk/main`。

## 12. 图片库 / 批量方案（只写设计，未改代码）

若要做「图片预览文库 + 批量」，按下面这条最省事：

1. **扫描**：从当前目录（如 `/照片/欣蓉`）或指定根做 BFS：`/api/list?web=1&num=100` 逐目录翻页；`isdir=1` 入队，文件按 `ImageTypes.EXTENSIONS` 或 `thumbs.ft=image` 收图；设上限（建议 400 目录 / 2000 张）与进度提示。
2. **宫格**：瓦片用 `thumbs.url2`（c360_u270，2~26 KB）或 `url1`（c140_u90，≈2 KB）；磁盘缓存 key 用 `THUMB_ID@size@ft`。
3. **看图**：点开用 `size=c2560_u2560`（等原图），**预取左右各一张**放进内存 LRU，翻页即秒切；「看原图/存原图」再回落 `dlink`。
4. **批量**：
   - 批量删除：`POST /api/filemanager?opera=delete&async=2&onnest=fail&newVerify=1`，body `filelist=["/绝对路径", …]`；**注意 `async=2` 的 `errno:0` 只代表入队**，要提示「已提交删除，稍后刷新确认」。
   - 批量导出：`/api/gettemplatevariable` 取 `sign1/sign2/timestamp/is_vip` → 逐个 `/api/download?type=dlink` 换 `dlink` → 下载原字节写 `MediaStore.Pictures`。
5. **过期自愈**：任何 403/非 JPEG 响应 → 重拉一次 `/api/list` 换新 `sign` 重试。

## 13. 未知与限制

- 网页端「看图」的实际网络请求**未抓包**（S），本文只验证了缩略图通道本身可用且尺寸可换；二者在效果上等价。
- `quality` 参与不参与签名、各档差异未逐项实测（保持 100 即可）。
- 缩略图有损，**不等于原图字节**；需要原图（HEIC、PNG 透明、EXIF、精确像素）必须走 `dlink`。
- `/api/search` 的 500 条上限是**观察值**（某目录 `.jpg` 检索恰好 500），不排除与服务端策略/账号有关。
- `/api/categorylist` 全空只代表**当前账号/当前版本**不可用。
- 8 小时是按 `expires=8h` + `time` 推断的有效期，未做跨 8 小时的失败边界实测。
- 接口均无公开契约，字段可能随版本变化；解析需容错（`thumbs` 缺失时回落原图链路）。

## 14. 复现方式（不含任何凭据）

在已登录的 `pan.baidu.com` 页面上下文里（例如 App 的隐藏 WebView 或浏览器 DevTools）执行：

```js
// 1) 取 bdstoken
const tpl = await (await fetch('/api/gettemplatevariable?clienttype=0&app_id=250528&web=1&fields=%5B%22uk%22%2C%22bdstoken%22%5D', {credentials:'include'})).json();
const token = tpl.result.bdstoken;

// 2) 列目录，拿 thumbs
const j = await (await fetch(`/api/list?clienttype=0&app_id=250528&web=1&channel=chunlei&bdstoken=${token}&dir=${encodeURIComponent('/照片/欣蓉')}&order=time&desc=1&num=100&page=1`, {credentials:'include'})).json();
const item = j.list.find(x => !x.isdir && /\.(jpe?g|png)$/i.test(x.server_filename));
console.log(item.thumbs.url3);

// 3) 换尺寸（浏览器外也能直接 curl，无需 Cookie）
const big = item.thumbs.url3.replace(/size=[^&]*/, 'size=c2560_u2560');
const bmp = await createImageBitmap(await (await fetch(big)).blob());
console.log(bmp.width, bmp.height);
```
