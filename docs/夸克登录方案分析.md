# 夸克网盘 · 登录方案分析（手机 WebView 滑块不显示 / 同机无法扫码 的替代方案）

> 版本：v1.0　生成日期：2026-11-10
> 背景：`docs/多网盘整合架构方案.md` 落地 P3 时，`QuarkProvider.login()` 需要在手机 WebView 里完成登录；当前遇到两个问题：
> ① 手机上「手机号码登录」的**拖动滑块验证码不显示**；
> ② **同一个手机**无法扫码登录（夸克 App 扫码 / 微信扫码都需要第二台设备）。
> 结论来源：web 前端包 `cloud-drive-web/4.6.7` 静态分析（登录入口/协议）+ 实测匿名可达性（H5 登录页、QR token 接口、su 短链跳转）。
> 标注：**S** = 前端源码观察；**R** = 本次实测；**D** = 设计推断。

---

## 0. 一句话结论

| 问题 | 根因 | 首选替代方案 |
|---|---|---|
| 手机号登录滑块不显示 | 加载的是 **PC 版登录页**（`client_id=532&display=pc`），滑块是阿里 **baxia/awsc**，对 WebView 环境高度敏感（UA/三方 Cookie/WebGL） | ① 改用 **H5 手机登录页**（`client_id=503&display=mobile`，滑块换成了触屏版 `aliyunCaptchaV2`，实测可达 **R**）；② 按 §5 清单修复 WebView 环境 |
| 同机无法扫码 | 扫码流程**结构性**需要第二台设备扫码确认 | **同机授权**：二维码的内容就是一个 URL（`https://su.quark.cn/4_eMHBJ?token=…`，**R**），在本机直接用 `Intent(ACTION_VIEW)` 打开它——等效于"自己扫自己"，本机装有夸克 App 即可完成确认（**D**，需真机验证） |
| 同机微信扫码 | 微信 OAuth 必须在微信 App 内确认，第三方 WebView 拉不起未注册的 appid | **无解，UI 按 `supports()` 隐藏微信入口**（D） |
| 兜底方案（不依赖任何登录页） | —— | **Cookie 导入**：PC 浏览器登录一次 → 导出 `.quark.cn` 域 Cookie → `CookieManager.setCookie` 注入 App WebView。App 内完全不出现登录页（**D**，最稳） |

## 1. 夸克登录入口全景（源码提取，S）

web 前端 `cloudDriveConfig` 旁的登录配置（`index.js`）：

```js
{
  scanLoginPage:     "https://su.quark.cn/4_eMHBJ",                                        // 扫码登录中转页
  mobileLoginPage:   "https://uop.quark.cn/cas/custom/login?custom_login_type=mobile&client_id=532&display=pc",   // 手机号(PC样式)
  passwordLoginPage: "https://uop.quark.cn/cas/custom/login?custom_login_type=common&client_id=532&display=pc",   // 账号密码(PC样式)
  h5LoginPage:       "https://uop.quark.cn/cas/custom/login?custom_login_type=mobile&client_id=503&display=mobile", // 手机号(H5触屏样式) ★
  wxLoginPage:       "/wechat_qrcode?need_bind_mobile=1",                                  // 微信扫码(相对 pan.quark.cn)
  forgotPasswordUrl: "https://uop.quark.cn/cas/forgotpassword?client_id=532&redirect_uri=",
  clientHost: "http://127.0.0.1", clientPorts: [9125,9126,9127,9128,9129,9130],            // 夸克PC客户端本地API
}
```

**client_id 语义**：`532` = 夸克网页（PC）；`503` = 夸克 H5（移动页）；`386` = acquireAppToken 所用（App token）；`573` = PC 客户端（走 native `dsg.encryption` 签名，仅桌面端）。

**关键实测（R）**：

- H5 登录页 `client_id=503&display=mobile` **匿名可达**（HTTP 200，标题「手机登录 无需注册」），其脚本列表里有 **`aliyunCaptchaV2_*.js`**——移动端验证码与 PC 的 baxia 滑块**不是同一套**，这是"手机滑块不显示"的直接解法之一。
- PC 版登录页（client_id=532）加载的是 `g.alicdn.com/sd/baxia`、`AWSC/awsc.js`、`fireyejs`（S，见 pan.quark.cn 首页脚本）。
- 扫码 token 接口**匿名可用**：
  `GET https://uop.quark.cn/cas/ajax/getTokenForQrcodeLogin` →
  `{"status":2000000,"message":"ok","data":{"members":{"token":"sta336333f8dy..."}}}`（R，2026-11-10 实测）。
- `su.quark.cn/4_eMHBJ?token=…` 302 到 `b.quark.cn/apps/DuJrlezmS/routes/…`（token 原样透传），该页是「在夸克 App 中打开」的中转页（R）。

## 2. 扫码登录协议契约（S + R）

web 端扫码登录完整流程（源码 `fetchTokenLoop` / `queryLoginSt`）：

| 步骤 | 请求 | 说明 |
|---|---|---|
| 1 | `GET https://uop.quark.cn/cas/ajax/getTokenForQrcodeLogin` | 取一次性 token（`data.members.token`），无需登录态（R） |
| 2 | 生成二维码内容：`https://su.quark.cn/4_eMHBJ?token=<token>&client_id=532&ssb=weblogin&uc_param_str=&uc_biz_str=S:custom\|OPT:SAREA@0\|...` | **二维码里就是一个 https 短链**（S：`Object(f.a)(u.a.scanLoginPage,{token:d,...})`） |
| 3 | 夸克 App 扫码 → 打开短链 → 中转页拉起 App（`qkclouddrive://` scheme，Info.plist 已注册）→ App 内确认 | 服务器把 token 标记为"已确认" |
| 4 | web 每 ~200ms 轮询 `GET https://uop.quark.cn/cas/ajax/getServiceTicketByQrcodeToken?token=<token>` | `status==2000000` → `data.members.service_ticket`（S） |
| 5 | 用 `service_ticket` 完成登录（官方页内部处理，写 Cookie；PC 客户端走 `account.getProfileByServiceTicket` + native 签名，S） | 自建流程**不要自己实现第 5 步**——直接内嵌官方登录页让它在 WebView 里自己写 Cookie |

> **同机授权的关键观察（D）**：二维码的内容是 URL 而不是私有协议。App 扫码做的事 = "打开这个 URL 并确认"。所以在**同一台手机**上，只要装有夸克 App，直接用 `Intent(ACTION_VIEW)` 打开这个 URL 就等于扫码——中转页会提示「用夸克 App 打开」→ scheme 拉起 → 确认 → web 端轮询拿到 ticket → 登录完成。
> 实现：内嵌官方扫码登录页（或自建：调接口 1 画自己的码 + 自己轮询接口 4），同时**监听二维码 div 的内容**（内嵌官方页时可对 `img.qrcode` 做 canvas 解码，或干脆自建二维码页），把 URL 转成本机 Intent。

## 3. 方案矩阵（按推荐顺序）

### 方案 A · Cookie 导入（推荐首发，零登录页依赖）

**思路**：登录这件事在 PC 浏览器上一次性完成（已有 Edge 登录态），把 Cookie 导入手机 App 的 WebView。

- 导出：PC 浏览器 DevTools → Application → Cookies，取 `.quark.cn` 域全部会话 Cookie（`__pus`、`__puus`、`__kp`、`__kps`、`__ktd`、`__uid`、`ctoken` 等，以实际导出为准）。
- 注入：Android `CookieManager.setCookie("https://.quark.cn", "name=value; ...")` 逐条写入；如需覆盖 `drive-pc.quark.cn` / `pan.quark.cn` 各写一遍。
- 验证：调 `GET drive-pc.quark.cn/1/clouddrive/config`（或 `file/sort` 根目录）看 `code==0`。
- UI：`LoginDialog` 增加「导入夸克 Cookie」粘贴框 + 校验按钮；失败给出明确文案。
- **优点**：绕开滑块/扫码/微信全部三个死结；与多网盘架构契合——`QuarkProvider.loginMode = COOKIE_IMPORT`。
- **缺点**：Cookie 过期（`__puus` 有时效且可能轮换）需重新导入；不适合分发给"普通用户"的产品形态，自用/小范围完全够用。

### 方案 B · H5 登录页 + 短信验证码（推荐内置，面向正常用户）

**思路**：不用 PC 版登录页，内嵌 **H5 手机登录页**：

```
https://uop.quark.cn/cas/custom/login?custom_login_type=mobile&client_id=503&display=mobile
```

- 实测可达（R），标题「手机登录 无需注册」，验证码脚本为 **aliyunCaptchaV2**（触屏版），交互按手机设计（zepto touch）。
- 登录方式 = 手机号 + 短信验证码（无需扫码、无需第二台设备）。
- 发短信前大概率仍会弹验证码，但已是移动端版本；配合 §5 的 WebView 修复清单，成功率显著高于 PC 版滑块。
- Cookie 由官方页登录成功后自动写入 WebView CookieManager（WebView 常驻，Cookie 不丢）。
- 注意：登录完成后 Web 层会重定向回网盘页，`WebViewClient.shouldOverrideUrlLoading` 里对 `pan.quark.cn/list#/`（或 `qkclouddrive://` scheme）做收尾识别。

### 方案 C · 同机授权（有夸克 App 时体验最好）

**思路**：复用扫码协议，但把"扫"改为"本机打开"。

1. 调 `getTokenForQrcodeLogin` 拿 token（匿名，R）。
2. App 内自绘二维码（展示给可能的第二台设备）**并同时**提供「本机已装夸克 App？点此授权」按钮 → `Intent(ACTION_VIEW, "https://su.quark.cn/4_eMHBJ?token=...&client_id=532&ssb=weblogin")`。
3. 中转页拉起本机夸克 App → 确认。
4. 轮询 `getServiceTicketByQrcodeToken` → 成功后**让官方页收尾**：最简单做法是把整个流程放在一个 WebView 里跑官方页面（官方页自己会做第 4/5 步）；自建轮询则需自行处理 ticket→Cookie（复杂，不建议）。
- 前置条件：本机装有夸克 App（scheme `qkclouddrive` 已由 QuarkCloudDrive.app/Android 包注册）。
- **需真机验证（U）**：夸克 App 对"非扫码来源打开授权链接"是否同样弹确认（大概率是，中转页本来就是给外部浏览器用的）。

### 方案 D · 修复 WebView 让 PC 版滑块可用（治本，配合 B）

滑块不显示通常是 WebView 环境不达标，逐项排查（§5）。

### 方案 E · 微信扫码 —— 放弃

- 微信网页登录（`open.weixin.qq.com` 二维码）必须用**微信 App** 扫码/确认；第三方 WebView 无法拉起未注册 appid 的 OAuth，同机无法完成。
- 处置：`QuarkProvider.supports(LOGIN_WECHAT)=false`，UI 直接不渲染该入口（能力声明式，与 §7 能力矩阵一致）。

### 方案 F · 夸克 PC 客户端本地 API（仅桌面端整合考虑）

- web 配置里有 `clientHost: "http://127.0.0.1"`、`clientPorts: [9125..9130]`：网页可探测本机安装的夸克 PC 客户端并调用其本地 API（含 `client.getClientInfo`、`dsg.encryption` 签名 bridge）。
- 仅适用于 **macOS/Windows 桌面版**整合（如后续做桌面端 App），手机不适用；且签名 bridge 是客户端私有 JS Bridge，Web 无法独立完成（S）。

## 4. 推荐组合（落地顺序）

1. **先上方案 A（Cookie 导入）**：工作量最小、立刻能用，作为 `QuarkProvider.login()` 的第一实现。
2. **随后加方案 B（H5 登录页）**：做成"登录 WebView"页，`h5LoginPage` + §5 修复清单，给正常用户自助登录。
3. **可选加方案 C（同机授权）**：检测到本机装有夸克 App（`PackageManager.getPackageInfo("com.quark.browser", 0)` 或查询 `qkclouddrive://` scheme）时显示"本机授权"入口。
4. UI 按 `supports()` 隐藏微信扫码。

## 5. WebView 环境修复清单（滑块不显示的排查项）

阿里 baxia/awsc 滑块对运行环境敏感，Android WebView 默认配置经常不满足。逐项检查：

| # | 配置 | 代码要点 | 说明 |
|---|---|---|---|
| 1 | **User-Agent** | `settings.userAgentString` 用**完整 Chrome 手机 UA**（含 `Chrome/xxx Mobile Safari`），去掉默认 WebView 标记 `; wv)` | baxia 对裸 WebView UA 高危处理：直接不渲染或必然失败。**这是最常见根因** |
| 2 | JS / DOM 存储 | `javaScriptEnabled=true`、`domStorageEnabled=true`、`databaseEnabled=true` | awsc 需要 localStorage |
| 3 | **第三方 Cookie** | `CookieManager.getInstance().setAcceptThirdPartyCookies(webView, true)`（API≥21） | baxia 验证组件走 `cf.aliyun.com` 等跨域 iframe，WebView 默认禁三方 Cookie |
| 4 | 硬件加速 | Activity/Window 级 `hardwareAccelerated=true`（默认 true，确认没被局部关闭） | 滑块图像渲染 |
| 5 | WebGL/Canvas | 不要禁；部分设备 WebView 关闭 GPU 光栅化会影响 | `chrome://flags` 不适用于 WebView；确保不是 `force dark`/省流模式 |
| 6 | 混合内容 | `mixedContentMode=MIXED_CONTENT_ALWAYS_ALLOW` | 静态资源 http/https 混用 |
| 7 | UA 一致性 | 同一 WebView 内不要中途改 UA（baxia 指纹校验前后一致性） | |
| 8 | 域名白名单（如做了请求拦截） | 放行：`uop.quark.cn`、`su.quark.cn`、`b.quark.cn`、`g.alicdn.com`、`image.uc.cn`、`image.quark.cn`、`cf.aliyun.com`、`broccoli.uc.cn`、`terms.alicdn.com` | H5 页引用了这些域（R） |
| 9 | 时区/语言 | 跟随系统即可，不要伪造 | 指纹一致性 |
| 10 | 排查手段 | `WebView.setWebChromeClient` 打 console 日志；`onConsoleMessage` 观察 baxia 报错 | 多数失败有明确 console 输出 |

> 修复后自测顺序：先在**系统 Chrome 手机浏览器**打开同一登录页确认滑块本身正常（排除账号风控），再在 App WebView 里复测；两者表现差异即环境差异。

## 6. 与多网盘架构的对接（D）

`CloudProvider.login()` 增加登录模式维度（写入 `多网盘整合架构方案.md` 的 SPI 扩展）：

```kotlin
enum class LoginMode { WEBVIEW_LOGIN, COOKIE_IMPORT, LOCAL_APP_AUTH, CLIENT_API }

interface CloudProvider {
    val loginModes: List<LoginMode>     // Quark: [COOKIE_IMPORT, WEBVIEW_LOGIN, LOCAL_APP_AUTH]
    fun loginUrl(mode: LoginMode): String?  // WEBVIEW_LOGIN → h5LoginPage URL
    // COOKIE_IMPORT: App 层提供粘贴框 + provider.validateSession() 校验
}
```

- `BaiduProvider`：`loginModes=[WEBVIEW_LOGIN]`（现有 wappass 页 + 验证码手动输入已可用）。
- `QuarkProvider`：`[COOKIE_IMPORT, WEBVIEW_LOGIN(h5), LOCAL_APP_AUTH]`，`LOGIN_WECHAT` 不支持。
- 会话校验统一：`GET drive-pc.quark.cn/1/clouddrive/config`（轻量、无需列表数据），`code==0` 即有效。
- Cookie 有效期：`__puus` 会轮换，App 端建议每次冷启动静默校验一次，失效则提示重新导入/重登（复用现有 `AccountScope` 会话管理，bucket 加 provider 维度后两套登录态互不干扰）。
