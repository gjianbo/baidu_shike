## 2. 核心接口草案（回调式，零新增依赖）

> D：沿用项目现有 `Executor + runOnUiThread` 模型，不引入协程。理由：百度 `evaluateJavascript` 本身是异步回调，包成 `suspend` 要自己写 `suspendCancellableCoroutine`，收益不抵复杂度。

```kotlin
enum class ProviderId(val id: String) { BAIDU("baidu"), QUARK("quark") }
enum class Method { GET, POST }
enum class DriveKind { VIDEO, AUDIO, PDF, DOCUMENT, DIRECTORY, OTHER }

data class DriveRef(
    val provider: ProviderId,
    val accountId: String,
    val fileId: String,          // 百度 fs_id / 夸克 fid
    val parentId: String,        // 夸克 pdir_fid；百度是「目录路径」（currentDiskDir() 返回值）
    val path: String,            // 完整路径：百度 rename/move/delete/createFolder 必需；夸克可由 info/path_list 补
    val name: String,
    val dir: Boolean,
    val kind: DriveKind,
    val size: Long = 0,
    val md5: String = "",
    val extra: Map<String, String> = emptyMap(),  // 厂商专有，通用层不解释
) {
    val key: String get() = "${provider.id}|$accountId|$fileId"
}

data class DrivePage<T>(val items: List<T>, val hasMore: Boolean, val nextPage: Int)

data class CaptchaChallenge(
    val imageUrl: String, val token: String, val raw: String,
)

sealed class DriveError(message: String) : Exception(message) {
    class AuthExpired : DriveError("登录态失效")
    class Captcha(val challenge: CaptchaChallenge) : DriveError("需要安全验证")
    class SecurityVerify(val op: String, val retryForm: String, val raw: String)
        : DriveError("需要百度安全验证")
    class Transcoding : DriveError("视频转码中")
    class NotSupported(val what: String) : DriveError("该网盘不支持 $what")
    class LinkExpired : DriveError("文件地址已过期")
    class Network(val detail: String) : DriveError(detail)
    class Unknown(val code: Int, val detail: String) : DriveError("[$code] $detail")
}

sealed class Playback {
    data class Hls(val url: String) : Playback()
    data class Progressive(val url: String) : Playback()
}

data class DriveSession(
    val provider: ProviderId,
    val accountId: String,
    val uk: String = "",
    val bdstoken: String = "",   // 仅百度；由 ensureBdstoken 结果写入，Provider 构造注入读取
)
```

**统一模型里没有 `gid` / `messageId` / `owner` / `Scope.GROUP`**（群组不兼容边界），但**必须保留 `path`** —— `path` 是通用字段，不是百度群组烙印：

| 百度侧依赖 `path` 的位置 | 说明 |
|---|---|
| `PanApi.kt:351` `renameItem` | `filelist` 里要 `path` + `newname` |
| `PanApi.kt:359` `moveItem` / `:379` `moveItems` | 要 `path` + `dest` + `newname` |
| `PanApi.kt:400` `deleteItems` | `filelist` 直接是路径数组 |
| `PanApi.kt:333` `createFolder` | 入参就是路径字符串（`diskPath(dir, name)`），不是 ID |

```kotlin
data class DriveRequest(
    val url: String,
    val method: Method,
    val body: String? = null,
    val contentType: String? = null,       // 百度 form-urlencoded / 夸克 application/json
    val lane: String = "default",
)

interface DriveTransport {
    fun send(request: DriveRequest, callback: (Result<JSONObject>) -> Unit): String  // 返回取消 token
    fun cancel(token: String)
}

interface DriveProvider {
    val id: ProviderId
    fun isLoggedIn(): Boolean
    fun accountId(): String
    fun list(parentId: String, page: Int, size: Int, cb: (Result<DrivePage<DriveRef>>) -> Unit)
    fun search(keyword: String, page: Int, size: Int, cb: (Result<DrivePage<DriveRef>>) -> Unit)
    fun resolveVideo(ref: DriveRef, cb: (Result<Playback>) -> Unit)
    fun resolveAudio(ref: DriveRef, cb: (Result<Playback>) -> Unit)
    // 百度是两步：diskDownloadSession() 取 sign1~3/timestamp/is_vip → diskDownload()；夸克一步 file/download
    fun downloadUrl(ref: DriveRef, cb: (Result<String>) -> Unit)
    // 两家都拿不到完整新节点：百度 WriteRequest 不含 fs_id，夸克返回 data.fid 但现有代码丢弃
    fun createFolder(parentId: String, name: String, cb: (Result<Unit>) -> Unit)
    fun rename(ref: DriveRef, name: String, cb: (Result<Unit>) -> Unit)
    fun move(ref: DriveRef, parentId: String, cb: (Result<Unit>) -> Unit)
    fun delete(ref: DriveRef, cb: (Result<Unit>) -> Unit)
}
```

**`createFolder` 统一返回 `Unit` + 由 UI 刷新列表**：百度 `WriteRequest(url, form)`(`PanApi.kt:308`) 没有新目录 fs_id，夸克 `QuarkPersonalDrive.create()` 也丢弃了 `data.fid`；硬要返回 `DriveRef` 就得百度侧补一次 list 查询，首版不值当。

**能力差异不用 `supports()` 硬对齐**：夸克无 copy、无群组，百度独有 copy / 群组 / 转存。这些留在各自 UI（或 provider 扩展），不进 9 方法交集，避免大量 `NotSupported` 抛异常。

```kotlin
data class BrowserState(
    val trail: List<DriveRef> = emptyList(),
    val query: String? = null,
    val items: List<DriveRef> = emptyList(),
    val page: Int = 1,
    val hasMore: Boolean = false,
    val busy: Boolean = false,
    val moveSource: DriveRef? = null,
)

interface DriveBrowserView {           // UI 渲染契约，无 Android 类型
    fun render(state: BrowserState)
    fun showError(error: DriveError)
    fun requireLogin()
}
```

> **首版 Controller 不接管筛选 / 排序**：百度 disk 页的 `filterBar` / `hasFilterOptions` / `addFilteredCourseRows` 与 group 流共用，接管会扩大改造面。状态机只管目录栈、搜索、分页、移动、加载态；筛选留在 UI 层，Phase 2 再说。

> **JVM 单测边界**：`JSONObject` 是 Android framework 类，纯 JVM 单测里不可用。Step 1 单测只覆盖不碰 `JSONObject` 的纯 Kotlin（`DriveRef` / `DriveKind` / `DriveError` 映射 / `BrowserState` 状态机）；Provider 解析层要测需 Robolectric 或 `org.json:json`，首版不做。

## 3. 关键技术点：百度传输层怎么剥离

`MainActivity.load()`（:6385-6538）目前把请求和 UI 混在一起。**包装时只搬「fetch + 轮询 + 原始 JSON」，以下 11 类副作用留在 Activity**：

| # | 现有耦合 | 代码位置 | 归属 |
|---|---|---|---|
| 1 | `ready` / `hasVerifiedAccount()` 前置检查 | :6398 | `SessionManager` |
| 2 | `RequestLane` 7 个 requestId / `isCurrent()` 取消判定 | :6402-6421 | `DriveBrowserController` 的 requestToken |
| 3 | `dismissMediaCaptcha(lane)` | :6411 | UI，请求前清理弹窗 |
| 4 | `playToken` / `AudioPlayRequestGate` / `cancelPendingAudioRequest` | :6412/:6421/:6462 | 音频播放门控，留 MainActivity |
| 5 | `status.text` / `updateAudioRequestMessage` / `failAudioRequest` | :6430/:6422-6429 | `DriveBrowserView.render / showError` |
| 6 | `onCaptcha` 弹窗 / `showSecurityVerify` | :6512 / `submitWrite` :3520 | `DriveError.Captcha / SecurityVerify` 抛给 UI |
| 7 | `errno == -6` 时 `invalidateAccount() + refresh()` | :6498-6505 | `DriveError.AuthExpired` + 会话失效通知 |
| 8 | `errno == 2156`（搜索无结果） | :6507 | `DrivePage(items=empty)`，不是错误 |
| 9 | `onCurrentResult`（带 `isCurrent` 的异步结果回调） | :6509/:6515 | Controller 的 requestToken 判定 |
| 10 | `acceptAnyErrno`（写操作要自己读错误码） | :3514 | Transport 只返回原始 `JSONObject`，errno 由 `BaiduProvider` 判 |
| 11 | 启动失败分支 `started != "true"` | :6533-6536 | `DriveError.Network("网盘页面尚未就绪")` |

### 3.1 bdstoken 循环依赖（v0.2 关键修正）

`MainActivity.ensureBdstoken()`（:2372-2397）**自己调用 `load()`** 去取 `gettemplatevariable` 里的 `uk` / `bdstoken`，而 `load()` 正是 `BaiduWebViewTransport` 要包装的对象。若直接包装，会形成：

```
SessionManager 要 bdstoken → ensureBdstoken → load() → BaiduWebViewTransport
  → DriveProvider → DriveRepository → SessionManager   （环）
```

且 `PanApi.diskList(:244)` / `createFolder(:333)` / `fileManager(:339)` / `diskAudioPlaylist(:284)` / `diskDownload(:292)` **全部要求 token 入参**，v0.1 的 `DriveProvider` 接口却没有 token 参数。

**处置（已定）**：

| 项 | 规则 |
|---|---|
| `ensureBdstoken` 的这一次请求 | **仍走原始 `load()`，不进 `BaiduWebViewTransport`**，避免成环 |
| 取到 `uk` + `bdstoken` 后 | 写入 `SessionManager` 的 `DriveSession` 并缓存（`bdstoken` 已有 `if (bdstoken.isNotEmpty())` 短路，:2373） |
| `BaiduProvider` | 构造注入 `DriveSession`，从 session 读 token；**接口方法签名不暴露 token** |
| 会话失效 | `-6` / 账号切换时清空 `DriveSession.bdstoken`，下次自动重取 |

### 3.2 错误码映射（UI 只认 `DriveError`）

| 百度 errno | 夸克 code | DriveError |
|---|---|---|
| `-6` / 401 / 403 | `21001` / HTTP 401 | `AuthExpired`（同时清 `bdstoken`） |
| `-20` | — | `Captcha(CaptchaChallenge)`，载荷含图片 URL + `vcode_str` + 原始 JSON |
| `132` | — | `SecurityVerify(op, retryForm)`，`retryForm` 带 `newVerify=1`（见 `PanApi.kt:404`） |
| `2156` | — | 空结果（不是错误） |
| `31341` | `21002` | `Transcoding` |
| `31304` | `21004` / `26001` | `NotSupported` |
| 其它 | `14001` / `21111` / `41060` / 其它 | `Unknown(code, message)` |

> 顺带修掉两处已查明的偏差：错误提示要**透传服务端 `message`**（现有 `QuarkPersonalDrive.request()` :159 没透传）；`delete` 继续用 `action_type=1`（同步，符合接口分析 §2.7 备注），v0.1 §10 写成 2 是笔误。

## 4. 登录与会话（修正 v0.1 被证伪的前提）

| 项 | 设计 |
|---|---|
| `SessionManager` 职责 | 「读取当前登录态 / 校验 / **持有并缓存 `uk` + `bdstoken`** / 失效通知」，**不负责打开登录页** |
| 百度会话 | WebView Cookie + `uk` + `bdstoken`；`ensureBdstoken()`(:2372) 原位保留，其结果写入 `DriveSession`（见 §3.1） |
| 夸克会话 | `hasLoginCookie()` 判 `__pus`/`__puus`；登录走真机扫码或「导入 Cookie」入口 |
| 登录 UI | 保留 `QuarkDriveActivity.showLogin()` / `showCookieImport()` 原样，不进通用层 |
| Cookie 域隔离 | `CookieManager` 全局但按域隔离（`baidu.com` vs `quark.cn`），双登录态天然不冲突 |

## 5. 数据迁移（复用 `AccountScope`）

`AccountScope.kt` 已有 `migrated_v1` 迁移器（`NAMESPACED` 列出 5 个 SharedPreferences：`audio_history` / `video_history` / `favorites` / `video_progress` / `course_cache`）。新增 `migrated_multi_v2`：

| 项 | 规则 |
|---|---|
| 旧 key | `acct_<uk>__*` |
| 新 key | `acct_baidu_<uk>__*`（夸克用 `acct_quark_<id>__*`） |
| 迁移方式 | **只复制不删**，写标记；与 `migrated_v1` 同款 `copyValue` |
| 夸克 accountId | **首版固定 `quark_default`**。`__uid` Cookie 是否稳定账号标识**未验证（U）**，若用作分桶键，重新登录/换设备可能导致收藏与进度漂移；待实测确认后再切 |
| 条目身份 | 统一 `DriveRef.key = provider|accountId|fileId` |
| 群组来源 | **不迁移、不改造**，继续用现有 `account_scope` 的 `group_id` |

## 10. 验收总纲

1. **每个 Step 单独提交**，编译 `gradle :app:assembleDebug` 通过，模拟器实测通过后才进下一步。
2. **Step 0 提交内容检查**：`git show --stat` 不含 `.DS_Store` / `.learnings/` / `.codex-attachments/`。
3. **百度零回归**：Step 3 前后逐项对比 disk 与 group（列表、搜索、分页、写操作、播放取址、收藏、进度）；**Step 4 只验夸克页**，百度页与 group 页不在对比范围。
4. **夸克逐条对齐实测契约**：对照 `夸克网盘接口分析.md` §11，在 **Step 2b** 内把 8 个能力逐块跑完并留记录。
5. **bdstoken 链路检查**：`ensureBdstoken` 不经过 `BaiduWebViewTransport`；账号切换 / `-6` 后 `DriveSession.bdstoken` 被清空并能自动重取。
6. **抽象泄漏检查**：`drive/` 包内 grep 不得出现 `gid` / `messageId` / `owner` / `fs_id` / `streaming` / `filemanager`；**允许 `path`**；`bdstoken` 只允许出现在 `DriveSession` / `SessionManager` / `BaiduProvider` 构造参数中。
7. **回滚**：任一步失败 `git revert` 该步提交即可，不牵连其它层。
